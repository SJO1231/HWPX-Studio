# 범위가 정해진 작업 위임

사용 가능한 Agent 도구와 현재 승인 범위를 확인한 뒤 적용한다.
위임이 허용되지 않거나 분리 이득이 없으면 직접 또는 순차로 수행한다.

## 나눌지 판단

- 서로 독립된 결과·파일 소유·수용 조건을 정할 수 있는가?
- 설명·대기·통합 비용보다 위임 이득이 큰가?
- 부모와 하위 Agent가 같은 구현이나 검사를 중복 수행하지 않는가?
- 모호한 요구를 단순 작업처럼 내려보내지 않는가?

가능할 때만 아래 역할을 현재 환경의 실제 역량에 대응시킨다.
모델 이름으로 역할을 고정하거나 존재하지 않는 Agent를 호출하지 않는다.

| 역할 | 책임 |
| --- | --- |
| 총괄 | 요구·분해·통합·최종 검증·사용자 보고 |
| 구현 담당 | 모호하거나 영향 큰 구현·통합 |
| 제한 작업 담당 | 요구 확정·국소 영향·낮은 위험의 작업 |
| 조사 담당 | 읽기·검색·목록화·근거 추출 |

## 인계문

하위 Agent가 부모 대화를 모른다고 가정한다.
다음 정보를 과업에 필요한 만큼 넣는다.

- 목표, 배경, 사용자의 중요한 제약
- 현재 기준 상태와 필요한 근거 파일
- 해야 할 일 / 하지 않을 일
- 수정 허용 파일·영역 / 다른 담당자의 소유 범위
- 기대 산출물과 관측 가능한 성공 조건
- 실행할 검증 또는 검증을 선택할 근거
- 중단 조건: 범위 확장, 새 계약 결정, 충돌, 자원·권한 부족
- 반환할 내용: 결과, 변경 경로, 검증 대상·명령·결과, 미해결 사항

읽기 전용 과업이면 이를 명시한다.
사실·경로·관련 발췌를 돌려받고 전체 원문 덤프는 요구하지 않는다.

## 실행과 통합

- 같은 파일을 동시에 수정하는 과업은 순차화하거나 담당을 다시 나눈다.
- 도구가 허용하면 적절한 기존 Agent를 재사용한다. 불필요한 재귀 위임을 만들지 않는다.
- 하위 Agent가 보고한 실패를 부모가 같은 조건으로 되풀이하지 않는다. 새 가설·범위·담당을 판단한다.
- 반환된 요약뿐 아니라 실제 변경과 근거를 확인한다.
- 통합 후 새로 생긴 변경과 필수 최종 검사만 재검증한다.
- 완료 책임은 총괄에 남는다. 위임하지 않았으면 여러 Agent가 검증했다고 보고하지 않는다.

이 Skill은 전역 모델 설정, 권한 정책, 외부 메시지 발송을 변경하지 않는다.
