# 세션 인계와 재개

현재 상태를 복구할 수 있는 최소 기록을 만든다.
대화 요약을 현재 코드의 사실이나 새 승인으로 취급하지 않는다.

## 인계할 때

1. 기존 이슈·작업 기록·인수인계 문서가 있는지 찾는다. 같은 목적의 두 번째 기록을 만들지 않는다.
2. 현재 브랜치·커밋 또는 파일 상태, 사용자 변경과 이번 변경, 남은 프로세스·작업 공간을 확인한다.
3. 아래 항목 중 필요한 것을 실제 근거와 함께 기록한다.
4. 기록을 다시 읽어 다음 담당자가 추측 없이 첫 행동을 할 수 있는지 확인한다.

### 기록 항목

- 요청한 결과와 범위 / 비범위
- 기준 상태: 날짜, 저장소·브랜치·커밋, 미커밋 변경
- 실제 완료한 것 / 아직 하지 않은 것
- 실행한 검사: 대상 상태, 명령, 결과, 근거 경로
- 미실행 검사와 필요한 자원
- 결정과 이유 / 가설 / 기각된 접근과 기각 근거
- 사용자 승인 범위와 미해결 질문
- 다음 행동 한 가지와 그 성공 조건
- 현재 차단요인·실행 중 작업·소유 파일

비밀값과 사용자 데이터 원문은 복제하지 않는다. 재현 가능한 안전한 입력이나 경로를 남긴다.

## 재개할 때

1. 기록의 날짜·기준 상태와 현재 파일·Git 상태를 대조한다.
2. 완료 표시를 믿기 전에 해당 산출물과 핵심 근거가 존재하는지 확인한다.
3. 바뀐 파일·환경·요구 때문에 무효화된 검증만 갱신한다. 이미 확인한 조사를 전부 반복하지 않는다.
4. 과거 가설을 확정 원인으로, 과거 제안을 사용자 승인으로 바꾸지 않는다.
5. 다음 행동이 현재 요청과 승인 범위에 맞으면 계속한다.

## 결정·교훈의 장기 보존

현재 작업에 필요한 결정은 기존 기록에 남길 수 있다.
다른 작업에도 적용할 규칙으로 승격하기 전에는 적용 범위·근거·재검토 조건을 따로 확인한다.
개인 또는 전역 메모리는 사용자 요청 없이 갱신하지 않는다.

과거에 실패한 접근도 전제가 바뀌었다면 재검토할 수 있다.
재검토 이유 없이 같은 실패를 반복하지 않는 것이 목적이다.
