## 0. 참고 경계 (규칙)

- 아래 프로젝트는 **원리만** 참고한다. 코드, 함수·변수·상수 이름, 주석, 파일 구조를 가져오지 않는다.
- 구현은 [엔진 명세](engine-spec.md)에서 출발한다. 명세에 없는 이름을 참고 소스에서 따오지 않는다.
- 런타임에 넣는 제3자 코드는 rhwp(뷰어·편집창)뿐이다. 나머지는 개발·검증에서 결과를 대조하는 오라클로만 쓰고 배포물에 넣지 않는다.
- AGPL·LGPL·라이선스 미표기 저장소는 원리 참고 대상에서도 뺀다.
- 식별자 대조 점검(2026-10-01): 우리 코드의 선언 이름 1,875개를 kordoc(1,280개), python-hwpx(518개), rhwp WASM API(907개)의 이름과 기계 대조했다. rhwp와는 겹침 0. kordoc 18개, python-hwpx 27개가 겹쳤고 대부분 흔한 낱말(`anchors`, `compare`, `header`, `fields`)이나 HWPX 요소 이름(`charPr`, `tc`)이다. kordoc의 함수 이름과 같던 넷은 바꿨다. `HwpxDocument`, `HwpxPackage`, `HwpxError`, `EditPlan`, `ValidationReport`, `ValidationIssue`는 python-hwpx의 클래스 이름과 겹치지만 형식 이름에서 나온 설명적 이름이라 그대로 뒀다. 우리 코드에 제3자 저작권·라이선스 문구는 없고 런타임 의존성도 없다.

## 1. rhwp (edwardkim/rhwp, MIT)

- Rust로 만든 HWP/HWPX 파서·조판·렌더러·편집 엔진. CLI, MCP 서버, WASM(`@rhwp/core`), 웹 편집기(`@rhwp/editor`, rhwp-studio), 데스크톱(Tauri) 등을 함께 둔다. 최신 릴리스 v0.8.6(2026-09-02) **[소스]**.
- 이 프로젝트에서의 역할: **뷰어와 편집창**(런타임), CLI는 검증 오라클.
- WASM `HwpDocument` **[소스]**: 페이지 SVG 렌더, 좌표→문서 위치 변환(구역·문단·글자 오프셋), 페이지 글자 배치(글자별 X 경계), 전체 검색, 필드 목록·값 설정, 텍스트·문단·표 삽입, 글자·문단 모양 적용, HWPX 내보내기. 초기화 전에 글자 폭 측정 콜백(Canvas)을 등록해야 한다.
- 편집기 임베드는 iframe 방식이고 HTTP(S) origin만 지원한다 **[문서]**.
- CLI **[실행]**: 검색이 `구역·문단·글자 오프셋·쪽·셀` 주소를 준다. 렌더 트리(글줄 bbox와 문단 인덱스), 페이지 SVG, 쪽 수, 필드 목록, 두 문서의 IR 비교, HWPX 왕복 게이트, 선언적 편집 계획 실행(입력 해시 전제, 조건, 저장 전 재검증, 모의 실행)이 있다.
- 한계 **[소스·실행]**: HWPX 저장은 내부 표현 전체를 다시 직렬화한다(패키지 항목 추가, 이진 자료 이름 변경, 새 객체 id 0). 바이트 보존 모드가 없다. 문서 간 조각 가져오기가 없다(클립보드는 같은 문서 안). 글자 모양 적용에서 인식하지 못한 키는 오류 없이 무시된다. 한컴과 조판이 같다는 보증이 없다(쪽 수 비교 13건 중 12건 일치).
- 알려진 결함 사례 **[문서]**: 누름틀에 안내문과 같은 값을 넣으면 성공을 보고하면서 값이 비던 문제(수정됨). 교훈: 채운 값을 다시 읽어 대조한다.

## 2. kordoc (chrisryugj/kordoc, MIT)

- TypeScript. 한국 문서 파싱·양식 채움·렌더·검증. main v4.17.4(2026-09-30) **[소스]**.
- 참고한 원리:
  1. **구간 치환**: 정규식 토크나이저로 본문 텍스트 구간의 원본 오프셋을 추적하고, DOM 재직렬화 없이 문자열 구간 치환만 한다.
  2. **ZIP 제자리 재조립**: 바꾸지 않은 항목은 원본 레코드 바이트를 그대로 복사하고 바꾼 항목만 다시 압축한다.
  3. **조판 캐시 제거**: 텍스트가 바뀐 구역의 줄 배치 캐시를 전부 지운다. 남기면 한컴이 변조 경고를 낸 사례가 있다. 한글 2024 대조에서 전체 삭제·부분 삭제·미삭제 모두 열리고 렌더가 같았다는 기록도 있다(버전별 동작은 불확실).
  4. **누름틀 채움**: 값 영역은 시작 컨트롤 뒤부터 끝 컨트롤 앞까지. 이름은 정확 일치만. 안내문과 값을 비교하지 않고 치환한다. 값이 있으면 `dirty`를 켠다.
  5. **양식 인식**: 라벨 셀 판정(키워드, 짧은 명사형, 수량·서술형·법인명 제외), 인접 라벨→값 셀, 헤더행+데이터행 표, 인라인 `라벨: 값`, 괄호 빈칸·체크박스·밑줄, 값 패턴 우선의 타입 추론, 필수 표시, 빈값 판정.
  6. **매칭**: 정규화 후 정확 일치 → 접두사 일치(길이 비율 임계), 배열 값은 등장 순서대로 소진, 같은 키가 여러 곳에 걸리면 거부하고 보고.
  7. **검증**: mimetype 첫 항목, 필수 파일, XML 정형성, header의 구역 수 선언과 실제 구역 파일 수 일치(불일치면 한컴독스가 열기 거부), manifest 참조 실존.
  8. **렌더**: 한컴이 저장한 줄 배치 캐시 좌표를 그대로 써서 그린다. 캐시가 없으면 자체 줄나눔으로 근사한다.
- 한컴 거부·경고 사례 **[문서]**: 남은 줄 배치 캐시(변조 경고), XML 금지 제어문자(한글 2024 손상 거부), 표 필수 속성 누락(macOS 한컴 거부), 미리보기 텍스트 부재.
- 이 프로젝트에서의 역할: 원리 참고. 개발 환경에서는 결과 대조 오라클(MCP)로 쓸 수 있다.

## 3. hwpx-filler (rfastball/hwpx-filler, MIT)

- Python + React. 표 데이터의 행마다 누름틀 HWPX 템플릿을 채워 일괄 생성한다. v0.9.0(2026-09-29) **[소스]**.
- 참고한 원리:
  1. **rhwp를 저작 작업대로 쓰는 방식**: 편집기(WASM)를 동봉하되, 호스트가 문서 상태·저장·구조를 소유하고 편집기는 표시·선택·편집만 맡는다. 편집기 자체 복구 기능은 끈다.
  2. **round-trip 동일성 게이트**: 원본과 편집기가 내보낸 문서를 정규화해 비교하고, 증명된 기본값 차이 외에 하나라도 다르면 편집을 막는다(실패 닫힘).
  3. **`{{이름}}`을 누름틀로 컴파일**하는 저작 보조. 읽기 전용 미리보기와 변형 단계를 분리한다.
  4. **split-run 정책**: 같은 글자모양의 인접 조각만 한 덩어리로 본다. 탭·줄바꿈·컨트롤·다른 글자모양을 가로지르면 추측하지 않고 건너뛰어 보고한다.
  5. 수정한 구역만 다시 쓰고 줄 배치 캐시를 지운다. ZIP은 결정적으로 조립한다. 생성 뒤 다시 읽어 확인하고 원장을 남긴다.
  6. 하이퍼링크 필드는 채움 대상에서 뺀다(거부 목록 방식).

## 4. python-hwpx (airmang/python-hwpx, Apache-2.0)

- Python. HWPX 읽기·편집·병합. v6.6.0 **[문서]**.
- 참고한 원리:
  1. **보존 계약**: patch 방식에서 미수정 항목의 바이트 동일을 달성하지 못하면 아무것도 쓰지 않는다.
  2. **문서 병합 계약**: 다른 문서의 본문을 끼워 넣으면 공유 자원 id가 다른 뜻으로 재사용된다. 해법은 복사가 아니라 재매핑이다. 축은 셋: 서식 자원(글꼴은 언어별 독립 id 공간), 이진 자료, 문서 안 id(문단·표·그림, 필드 짝).
  3. **함정**: 편집한 문단의 줄 배치 캐시를 지우지 않으면 한컴이 옛 줄 자리에 새 글자를 그려 겹친다. 구역 설정이 든 run을 통째로 지우면 같은 run의 표·글이 사라진다. 문서 맨 앞에 삽입할 때 구역 설정의 위치가 어긋나면 한컴이 새 절의 시작으로 읽는다.
- 개발 환경에서는 결과 대조 오라클로 쓸 수 있다.

## 5. 그 밖

| 프로젝트 | 내용 | 판단 |
| --- | --- | --- |
| hwp.js | HWP5 뷰어. HWPX 미지원, 정체 | 대상 아님 |
| hwpx 생성기류(JS) | Markdown·HTML에서 새 HWPX 생성 | 기존 문서 보존 패치가 아님 |
| hwpxlib, hwplib (Java, Apache-2.0) | 객체 모델 읽기·쓰기 | 참고만 |
| hwpx-owpml-model (한컴 공식, C++) | OWPML 요소 모델 | 구조 확인용 |
| docx 템플릿 도구들 | 쪼개진 run에 걸친 태그 처리: 문단 텍스트를 이어 붙여 탐색 → 오프셋을 원래 조각으로 역매핑 → 첫 조각에 모으고 나머지를 비움 | 원리 참고 |

- HWPX를 서식 보존으로 패치하는 성숙한 TypeScript 라이브러리는 kordoc 하나로 보인다 **[문서]**.
- AGPL 라이선스의 TypeScript HWPX 라이브러리가 있다. 참고 대상에서 뺀다.
