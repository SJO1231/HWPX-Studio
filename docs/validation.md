# 검증 기준

- 작성일: 2026-10-01
- 이 문서가 소유하는 주제: 저장 게이트, 검사 항목, 보존 계약, 조각 동일성 기준, 오라클, 수용 시나리오
- 원칙: **파일을 만들었다는 것과 문서가 정상이라는 것을 같은 것으로 취급하지 않는다.** 검증을 통과하지 못하면 출력 파일을 만들지 않는다.

## 1. 저장 흐름

```
원본 → 작업 사본(메모리) → 편집 계획 → 모의 실행 보고 → 적용 → 재파싱 → 검사 → 기준선 대조
     → 보존 계약 검사 → 채운 값 재읽기 대조 → (선택) 오라클 교차 → 통과 시에만 저장 → 원장
실패: 아무것도 쓰지 않는다. 원본은 그대로다.
```

## 2. 저장 게이트 세 방식

| 우선순위 | 방식 | 동작 | 쓰는 때 |
| --- | --- | --- | --- |
| 1 (기본) | `baseline` | 원본의 검사 결과를 기준선으로 둔다. 편집이 **새로 만든** 오류만 저장을 막는다. 원본에 이미 있던 오류는 경고로 보고한다 | 일반 |
| 2 | `strict` | 오류가 하나라도 있으면 막는다 | 새로 만든 문서, 납품 전 점검 |
| 3 | `repair` | 안전하게 다시 매길 수 있는 것만 고친 뒤 진행한다: 중복된 객체 id·instId, 필드 짝 id. 없는 서식 참조는 고치지 않고 보고한다 | 원본 오류 때문에 작업이 막힐 때 |

근거: 실제 문서 659건 중 한컴류 15%에 id 중복·없는 참조가 원래 있었다. 엄격 방식만 두면 이 문서들은 편집 전에 거부된다. 없는 참조를 임의의 서식으로 돌리는 수리는 문서의 뜻을 바꾸므로 하지 않는다.

## 3. 검사 항목

| 영역 | 검사 |
| --- | --- |
| 패키지 | ZIP 읽기·CRC, 항목 이름 중복, `mimetype` 첫 항목·무압축·값, 필수 항목 존재, rootfile, manifest의 href·id·spine, 구역이 manifest에 있는지, 이진 자료와 manifest 대조, 모든 XML 정형성, header의 구역 수 선언과 실제 구역 파일 수, XML 금지 제어문자, 미리보기 텍스트 존재(경고) |
| 자원 | 자원 목록의 id 집합과 중복, 자원 사이 참조와 본문 참조(`charPrIDRef`, `paraPrIDRef`, `styleIDRef`, `nextStyleIDRef`, `borderFillIDRef`, `tabPrIDRef`, numbering·bullet 참조, `fontRef`, `binaryItemIDRef`)의 대상 존재, `itemCnt` |
| 인스턴스 | 문단 id, 객체 id, instId, 필드 id의 중복(구역을 가로질러), 책갈피 이름 중복 |
| 구조 | 필드 시작·끝 짝과 순서, 표 중첩 깊이·셀 범위·행열 수·필수 속성, 모르는 컨트롤 목록(경고) |

- 한컴이 여러 문단에 같이 쓰는 자리값 id는 중복으로 세지 않는다(관측에 근거한 가정).
- 한컴이 받아 주는 것으로 관측된 위반은 경고로 두고 `strict`에서 오류로 올린다. 해당하는 것은 셋이다: 탭 목록이 비었는데 문단모양이 탭 0번을 가리킴, 쪽 테두리의 테두리 0번 참조, 객체 id·instId가 0으로 겹침.
- 오류·경고 코드는 기존 Python 검사기와 같은 이름을 쓴다(같은 프로젝트의 자산).

## 4. 보존 계약

출력은 원본과 비교해 아래만 달라야 한다.

- ZIP: 항목 이름 순서 동일. 수정하지 않은 항목의 로컬 레코드는 바이트 동일. 추가 항목은 이진 자료뿐이다.
- 수정한 구역 XML: 토큰 단위로 비교해 (a) 본문 텍스트 구간, (b) 지운 줄 배치 캐시, (c) 계획에 있는 삽입·삭제 블록, (d) 계획에 있는 속성값(필드 `dirty`, id 재발급) 외에는 같아야 한다.
- header: 자원 추가와 개수 속성 갱신만.
- manifest: 추가 항목만.
- 수량 대조: 문단·표·그림·필드·책갈피·모르는 컨트롤의 수가 계획이 예고한 증감과 같아야 한다.

## 5. 조각 동일성 기준

조각을 다른 문서에 넣은 뒤:

| 항목 | 기준 |
| --- | --- |
| 글 | 조각 안 모든 문단의 논리 텍스트가 원본과 같다 |
| 서식 | 문단·run·셀이 가리키는 글자모양·문단모양·테두리의 **지문**이 원본과 같다(글꼴은 이름으로 전개해 비교) |
| 참조 | 없는 대상을 가리키는 참조 0 |
| id | 중복 0. 필드 짝 오류 0. 책갈피 이름 중복 0 |
| 이진 자료 | 그림이 가리키는 항목이 있고 manifest에 등록돼 있다 |
| 대상 문서 | 원래 있던 문단·자원의 내용은 바뀌지 않는다 |
| 화면 | rhwp 렌더에서 이상 신호 없음. 한컴에서 열림(설치된 PC) |

## 6. 채운 값 재읽기 대조

저장 직전 출력 바이트를 다시 파싱해, 계획의 모든 자리에서 값을 읽어 넣으려던 값과 비교한다. 하나라도 다르면 저장하지 않는다. 안내문과 같은 값을 넣는 경우도 시험한다.

## 7. 오라클

| 오라클 | 확인하는 것 | 필요한 것 |

오라클이 없으면 해당 검사를 건너뛰고 결과에 "미검증"으로 적는다. 통과로 세지 않는다.

## 8. 수용 시나리오

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| E1 | 무변경 왕복 | 파일 전체 바이트 동일 |
| E2 | 누름틀 채움(안내문과 같은 값 포함) | 값 재읽기 일치, `dirty` 설정, 보존 계약 |
| E3 | 한 run 안의 `{{}}` 치환 | 값 일치, 보존 계약 |
| E4 | 여러 run에 걸친 `{{}}` | 같은 글자모양이면 치환, 경계를 가로지르면 skipped 보고 |
| E5 | 셀 앵커 채움 | 값 일치, 셀 서식 불변 |
| E6 | 누름틀 승격(`compile`) | 승격본이 검사 통과, 한컴에서 열림 |
| E7 | 조건 삭제(문단·표 행) | 수량 증감이 계획과 같음, 검사 통과 |
| E8 | 조건 주입(조각 + 데이터) | 조각 동일성 기준, 바인딩 값 일치 |
| E9 | 표·문단·그림 조각을 다른 문서로 | 5절 전 항목 |
| E10 | 누락 키 정책 | `error`는 파일 미생성, `empty`·`keep`은 보고와 함께 진행 |
| E11 | 원래 오류가 있는 문서 | `baseline` 경고, `strict` 차단, `repair` 재발급 뒤 통과 |
| E12 | 한컴 저장본 편집 | 줄 배치 캐시 제거, 쪽 수·수량 동일, 한컴 열림 |
| E13 | 서식 상속 텍스트 삽입 | 삽입 문단의 서식 참조가 영역과 같음 |
| E14 | 실문서 표본 50건 | 파싱·왕복·모의 실행에서 예외 0, 왕복 바이트 동일 50/50 |

## 9. 시험 자료 취급

- 시험은 임시 폴더의 사본으로만 한다. 사용자 폴더의 파일을 쓰거나 옮기거나 지우지 않는다. 전후 해시로 확인한다.
- 실제 문서의 이름과 내용을 기록·커밋하지 않는다. 결과는 수량과 코드로만 남긴다.
- 보고서와 원장에 값 원문을 남기지 않는다. 길이와 해시 앞부분만 남긴다.
