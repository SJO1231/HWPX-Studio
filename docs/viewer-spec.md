# 뷰어 명세

- 작성일: 2026-10-02
- 이 문서가 소유하는 주제: 뷰어(rhwp 임베드)의 계약 — 구성, 위치 변환, 시험 구현의 범위와 수용 조건
- 소유하지 않는 주제: 엔진 계약은 [엔진 명세](engine-spec.md), rhwp와 참고 프로젝트의 사실은 [참고 프로젝트](reference-projects.md)
- "결정"은 총괄의 임시 선택이다. 표기: **[실행]** 직접 실행해 관측 / **[소스]** rhwp 원본 소스 / **[미확인]**

## 0. 원칙

1. 뷰어는 표시와 선택만 한다. 문서 바이트와 구조의 소유자는 엔진(호스트)이다.
2. 화면 좌표를 문서 위치로 바꾸는 일은 rhwp가 한다. 우리는 rhwp가 준 위치를 엔진 주소로 옮긴다.
3. 글자 위치의 근거는 **포인터 아래에 그려진 글**이다. 옮긴 위치는 매번 글로 확인한다(rhwp가 그 자리에 그린 글 = 엔진 논리 텍스트의 그 자리 글). 확인이 안 되면 글자 위치를 버리고 문단 단위나 "위치 없음"으로 내려가며, 틀린 위치를 조용히 쓰지 않는다.
4. rhwp는 npm 배포본을 고친 것 없이 쓴다. 패치가 필요해지면 근거와 함께 보고하고 따로 정한다.
5. 뷰어 쪽 코드에도 참고 프로젝트의 코드·식별자를 가져오지 않는다. rhwp의 공개 API 이름은 의존 라이브러리의 API이므로 그대로 쓴다.
6. 외부 네트워크를 쓰지 않는다(글꼴 CDN, 외부 호스팅 편집기 포함).

## 1. rhwp 사실 (v0.8.6, 조사 2026-10-02)

- `@rhwp/core` 0.8.6, MIT. ESM, wasm-bindgen `web` 대상. 브라우저에서 번들러 없이 로드되고, Node에서는 wasm 바이트를 넘겨 초기화하면 된다 **[실행]**.
- 글자 폭 측정 콜백은 이 버전에서 쓰이지 않는다(조판은 내장 글꼴 메트릭). 글꼴이 없어도 줄·쪽 나눔과 좌표는 같고 모양만 달라진다 **[소스·실행]**.
- 문서는 `Uint8Array`로만 연다. 오류는 `Error`가 아니라 문자열로 던져진다 **[실행]**.
- 좌표: 쪽 왼쪽 위가 원점, y는 아래로, 단위는 96 DPI 픽셀. 배율은 화면(CSS) 쪽에서 준다. rhwp의 DPI 설정은 바꾸지 않는다 **[실행]**.
- 쪽 SVG에는 문서 위치 식별자가 없다. 위치는 좌표 API로만 얻는다.
- **클릭 위치**: 본문·표 셀·글상자는 `hitTest`가 `{ sectionIndex, paragraphIndex, charOffset, parentParaIndex?, cellPath?, isTextBox? }`를 준다. `cellPath`는 바깥 표부터 `{ controlIndex, cellIndex, cellParaIndex }`의 목록이다. 머리말·꼬리말·각주는 전용 함수가 있고, 그것을 먼저 부르지 않으면 본문 위치가 대신 나온다 **[실행]**.
- **쪽 글자 배치**: `getPageTextLayout`이 런마다 `{ text, x, y, w, h, charX[], secIdx, paraIdx, charStart, cellPath? }`를 준다. 번호·글머리표·쪽번호 런에는 문서 좌표가 없다. 런마다 첫 글자 순번(`charStart`)이 앞 개체를 세는 정도가 다르고, 클릭 위치 함수의 글자 순번과 어긋나는 경우가 있다(글자처럼 취급 개체·탭·글자 모양이 바뀐 런, 글 뒤·앞에 놓인 표, 런 상자가 겹친 자리, 다시 조판된 문단) **[실행: 실제 문서 160건에서 클릭의 0.76%]**. 그래서 글자 위치는 클릭 위치 함수가 아니라 이 글자 배치에서 구한다(3절).
- **글자 오프셋의 축**이 여럿이다. 글자 배치는 "유니코드 글자 순번 + 글자처럼 취급 개체(그림·글상자·수식) 1칸"이 기본이고, 검색·필드 목록은 "글자 순번"만이다. 표는 글자처럼 취급이어도 0칸이다. 탭·줄바꿈은 1칸, 누름틀 시작·끝과 구역 설정 같은 컨트롤은 0칸, 자동 번호는 공백 1칸이다. 안내문 상태 누름틀의 안내문은 글자 칸이 없고 좌표 없는 런으로 따로 그려진다 **[실행·소스]**.
- 각주 영역 판별 함수 가운데 "각주 안 위치"를 주는 것은 각주가 있는 쪽의 어느 점에서나 참을 돌려주고, 머리말·꼬리말 판별은 머리말이 없어도 여백에서 참을 준다. 바탕쪽 글은 본문 문단 좌표를 달고 나온다. 영역은 포인터 아래 런의 종류와 쪽 렌더 트리로 가린다 **[실행]**.
- 묶음 개체 안에 글상자가 여럿이면 어느 글상자의 글이든 같은 색인으로 나오고, 표 셀 안 도형의 글은 경로에서 한 단계가 빠진다. 이런 글은 엔진 주소로 옮길 수 없다 **[실행]**.
- `paragraphIndex`는 구역 최상위 문단의 0부터 순번이고 구역 설정이 든 첫 문단도 센다. 구역 순서는 `content.hpf`의 spine 순서다. `controlIndex`는 rhwp가 문단에서 센 컨트롤 목록의 색인이다(구역 설정, 단 설정, 쪽 번호 위치, 표, 그림, 누름틀 시작 등이 각각 하나. 누름틀 끝은 세지 않는다) **[소스]**.
- 캐럿 사각형 함수는 각주가 있는 문단에서 위치가 어긋난다. 강조 표시는 쪽 글자 배치의 `x + charX`로 직접 만든다 **[실행]**.
- 편집기(`@rhwp/editor`)는 iframe 방식이고 HTTP(S) origin만 받는다. 기본 주소가 외부 호스팅이라 그대로 쓰면 문서가 외부로 나간다. 편집창 단계에서 자체 제공으로 바꾼다. 시험 구현은 편집기를 쓰지 않는다.

## 2. 구성

```
[브라우저]  rhwp(WASM): 열기·쪽 SVG·클릭 위치·글자 배치
            뷰어 화면: 쪽 표시, 배율, 클릭·끌기, 강조 표시
                 │  HTTP(시험 구현) → 데스크톱 셸에서는 IPC
[호스트/Node]  엔진: 문서 바이트 소유, 파싱, 위치 변환, 앵커 초안, 채움·게이트
```

| 경로 | 내용 |
| --- | --- |
| `packages/viewer/src/rhwp/` | rhwp를 감싼 얇은 계층(열기, 쪽 정보, SVG, 글자 배치, 영역별 클릭 위치). Node와 브라우저 양쪽에서 동작. 오류는 `ViewerError{code}` |
| `packages/viewer/src/map/` | 위치 변환(rhwp 위치 ↔ 엔진 주소). 순수 함수. 엔진 모델을 입력으로 받는다. DOM과 WASM에 의존하지 않는다 |
| `packages/viewer/src/dom/` | 브라우저 화면(쪽 표시, 배율, 클릭·끌기, 강조 표시) |
| `apps/viewer-poc/` | 시험 구현 앱: Node 서버(정적 파일, 문서 열기, 위치 변환, 앵커 초안, 채움)와 웹 화면 |

- 엔진은 Node 내장 모듈을 쓰므로 호스트에서만 돈다. 브라우저 코드는 엔진을 import하지 않는다(타입 import는 가능).
- 의존성: 런타임 `@rhwp/core`(정확한 버전 고정). 번들러는 두지 않는다. 시험 구현 서버가 브라우저용 `.ts`를 Node의 타입 제거로 바꿔서 준다(임시 선택. 데스크톱 셸 단계에서 다시 정한다).
- 저장소 루트에 `THIRD_PARTY_NOTICES.md`를 두고 rhwp의 MIT 고지를 적는다.

## 3. 위치 변환 (`src/map/`)

**타입**

```ts
// rhwp 쪽 위치(글자 배치의 런에서 얻는다)
type RhwpPosition = {
  sectionIndex: number
  paragraphIndex: number          // 본문이면 최상위 문단, 셀·글상자 안이면 그 안의 문단 번호
  charOffset: number              // 런의 첫 글자 순번 + 런 안 순번
  parentParaIndex?: number
  cellPath?: { controlIndex: number; cellIndex: number; cellParaIndex: number }[]
}
type Shown = { text: string; start: number }        // 포인터 아래 런의 글과 그 첫 글자 순번
type EngineAddress = { sectionIndex: number; path: number[]; offset?: number }   // offset: 논리 텍스트의 UTF-16 오프셋
type Located   = { address: EngineAddress; precision: "char" | "paragraph"; reason?: string; trail: string[] }
type Unlocated = { precision: "none"; reason: string; trail: string[] }
// 문단 범위 끌기(#53): 두 끝이 같은 부모의 다른 문단이면 precision "paragraph", address는 시작 문단, span { sectionIndex, parentPath, from, to },
// drafts는 range 초안(makeRangeAnchor와 같은 지문)과, 시작 문단이 제목이면 headingRange 초안(makeHeadingRangeAnchor). mark는 없다(한 문단 구간만 강조한다).
// defaultDraftIndex는 막히지 않은 range 초안이 있으면 그것을 고른다. 한 끝을 풀지 못하면 그 끝의 사유(PARAGRAPH_NOT_FOUND 등)다.
// 시작·끝 깃발(#74): { flags: { start, end } }. 두 깃발의 문단으로 위 문단 범위 끌기와 같은 응답을 낸다(4절 "시작·끝 깃발").
```

**함수**

- `toEngineAddress(doc, pos, shown?, edge?, guide?): Located | Unlocated` — `edge`는 `start`(글자 앞쪽 절반), `trail`(글자 뒤쪽 절반), `end`(범위의 끝), `guide`(안내문 클릭)다. `guide`는 눌린 안내문 글이다.
- `locateInCell(doc, cell): Located | Unlocated` — 셀 안 빈 곳(표 경로의 행·열과 줄 후보)을 엔진 셀의 문단으로 옮긴다.
- `locatePicked(doc, picked, edge?): Located | Unlocated` — 화면이 정한 누른 자리(위치, 런의 글, 한계 `char`·`paragraph`, 사유, 뒤쪽 절반 여부)를 받아 주소로 옮긴다. 서버와 대조 도구가 이 한 경로를 쓴다.
- `toRhwpPosition(doc, address): RhwpPosition | undefined`
- `controlSlots(paragraph)`: 엔진 문단에서 rhwp의 컨트롤 색인 순서를 다시 만든 목록. 항목마다 엔진의 객체와 그 하위 목록을 가리킨다.
- `offsetTable(paragraph)`: 엔진 논리 오프셋과 rhwp 글자 순번의 대응표.

**누른 자리 정하기** (화면 좌표 → 위치)

1. 쪽 글자 배치에서 포인터를 담는 글자 상자(런의 글자 경계와 줄 높이)를 가진 런을 찾는다. 글이 빈 런은 후보가 아니다.
2. 문서 좌표가 있는 런이 하나면 그 런의 좌표와 런 안 순번이 위치다. rhwp의 클릭 위치 함수가 다른 자리를 말해도 런을 따른다.
3. 서로 다른 문단의 런이 겹치면 `none`(`OVERLAPPING_RUNS`). 같은 문단의 런끼리 겹치면 `paragraph`.
4. 문서 좌표가 없는 글(쪽 번호, 번호·글머리표, 각주 번호)이면 `none`(`UNPOSITIONED_TEXT`). 안내문 상태 누름틀의 안내문만 예외로 그 누름틀을 가리킨다(같은 자리에 같은 글의 안내문 누름틀이 엔진 문단에서 확인될 때).
5. 글이 없는 곳(여백, 줄 끝 뒤, 셀 안 빈 곳)은 가장 가까운 줄의 문단을 `paragraph` 정밀도로만 낸다(`NEAREST_LINE`). `char`는 내지 않는다.
   - 먼저 점을 담은 **가장 안쪽 표 셀·글상자**를 쪽 렌더 트리의 사각형으로 찾는다. 점을 담은 사각형이 여럿이면 가장 작은 것이 나머지 모두의 안에 있을 때만 그것을 쓴다(아니면 `none`). 같은 크기로 완전히 포개진 표 셀은 먼저 나온 표를 고른다(화면에서 구별할 수 없는 자리다).
   - **표 셀 안**: 화면은 렌더 트리의 표 경로(표를 담은 문단 번호, 컨트롤 번호, 셀의 행·열. 중첩이면 바깥부터)와 줄 후보(셀 사각형 안에 그려진 같은 표의 런을 가까운 줄부터 최대 12개)를 보낸다. 호스트가 엔진 표에서 **행·열로 셀**을 찾는다(rhwp의 셀 색인은 쓰지 않는다. 그 색인이 한 칸씩 밀린 표가 실제 문서에 있었다).
     - 후보가 그 셀의 문단이면 그 문단이다. 글이 빈 후보가 다른 셀의 것이면 건너뛴다(좁은 빈 셀의 빈 런은 이웃 셀 자리에 그려지기도 한다).
     - 글이 있는 후보가 다른 셀의 것이면 `none`(`CELL_MISMATCH`).
     - 후보가 없으면 셀의 첫 문단이다(글이 전혀 없는 표의 빈 셀). 셀 안에 안쪽 표만 보이면 그 표를 담은 셀 문단이다.
     - 표 경로가 엔진 표와 맞지 않으면 `none`(`CELL_NOT_FOUND` 등. 쪽 수준에 그려진 표가 대부분이다).
   - **글상자 안**: 그 글상자에 소속된 런만 줄 후보다. 본문 글상자만 식별한다(셀 안 글상자, 묶음 개체 안 글상자, 글상자 안 표는 `none`).
   - **셀·글상자 밖**: 본문 런만 후보이고, 그 문단이 rhwp의 클릭 위치 함수가 말한 문단과 같을 때만 낸다. 다르면 `none`(`NEAREST_UNCONFIRMED`).
   - 가장 가까운 줄은 행을 먼저 본다(점의 높이를 담는 줄, 없으면 세로로 가장 가까운 줄).
6. 영역(본문·표 셀·글상자·머리말·꼬리말·각주·바탕쪽)도 포인터 아래 런으로 먼저 가린다. 런 자신의 사각형이 렌더 트리의 어느 영역 글 상자와 같은지를 먼저 본다(본문 표의 넓은 빈 셀 상자가 바탕쪽 글을 덮어도 그 글은 바탕쪽이다). 그다음(글상자 안 글자는 셀과 같은 모양으로 나오므로 경로의 컨트롤 종류로 글상자임을 가린다), 런이 없을 때만 영역 함수로 가린다. 머리말·꼬리말 안 표 셀의 글은 본문 표 셀과 같은 모양의 좌표를 달고 나오므로, 쪽 렌더 트리의 머리말·꼬리말·각주·바탕쪽 글 사각형으로 가린다.

**주소로 옮기기**

- 구역: rhwp와 엔진 모두 `content.hpf`의 spine 순서다(실행으로 확인. spine에 없는 구역은 엔진만 뒤에 붙이고 rhwp는 보이지 않는다).
- 문단: 본문은 `path = [paragraphIndex]`. `cellPath`가 있으면 단계마다 `controlSlots`로 그 컨트롤의 엔진 객체를 찾고, 표면 `cellIndex`번째 셀의 하위 목록, 글상자면 그 하위 목록으로 내려간다. 엔진 주소의 하위목록 서수는 "그 문단 안 `subList`의 문서 순서"이므로 객체에서 서수로 바꾼다.
- 컨트롤 색인 규칙: 구역 설정 1, `ctrl` 안의 단 설정·머리말·꼬리말·각주·미주·자동 번호·숨은 설명·찾아보기 표식·누름틀 시작·쪽 숨김·쪽 번호·새 번호 각 1(누름틀 끝 0), 표·그림·도형·묶음 개체·수식·차트·글자 겹침·덧말·양식 개체·`switch`·연결선 각 1. run 직속 책갈피와 형광펜 시작·끝은 컨트롤이 아니다. 실제 문서 107,129개 문단에서 rhwp가 센 수와 같았다.
- 글자의 뒤쪽 절반을 눌렀고 바로 뒤가 안내문 상태 누름틀이면 누름틀 시작 표식 앞(앞 글자 바로 뒤)으로 옮긴다. 안내문을 건너뛴 자리로 가지 않는다.
- 오프셋: 문단의 조각을 훑어 대응표를 만든다. 런의 첫 글자 순번이 앞 개체를 덜 세는 경우가 있으므로, 런의 글이 엔진 글에서 이어지고 그 안에 개체가 끼지 않으며 순번이 `[글자 순번, 글자 순번 + 앞 개체 수]` 안인 자리가 **하나뿐일 때** 그 자리로 정한다.
- 확인 실패는 사유와 함께 내려간다.

| 정밀도 | 사유 | 뜻 |
| --- | --- | --- |
| `paragraph` | `TEXT_MISMATCH` | 글은 문단에 있는데 자리가 다르다 |
| `paragraph` | `AMBIGUOUS_RUN` | 같은 글이 허용 구간에 둘 이상 |
| `paragraph` | `LABEL_RUN`, `OBJECT_RUN`, `OBJECT_WIDTH_UNKNOWN:<종류>` | 번호 글, 개체를 글자처럼 그린 런, 칸 폭을 모르는 개체 뒤(그 개체에 걸친 런은 개체 앞 글자도 포함) |
| `paragraph` | `SHOWN_OUT_OF_RANGE`, `OFFSET_OUT_OF_RANGE`, `NO_SHOWN_RUN`, `LIMITED` | 순번이 런이나 문단 범위를 벗어남, 확인할 런 없음, 화면이 문단 한계로 보냄 |
| `paragraph` | `OVERLAPPING_RUNS` | 같은 문단의 런끼리 겹쳤다 |
| `paragraph` | `NEAREST_LINE` | 빈 곳을 눌러 가장 가까운 줄을 썼다 |

| `none` | `SECTION_NOT_FOUND`, `PARENT_PARAGRAPH_MISSING`, `CONTROL_NOT_FOUND`, `CONTROL_KIND_UNKNOWN`, `CONTROL_NOT_CONTAINER`, `CELL_NOT_FOUND`, `CELL_PARAGRAPH_NOT_FOUND`, `TEXTBOX_AMBIGUOUS`, `PATH_INCONSISTENT` | 경로를 풀 수 없다(묶음 개체, 표 셀 안 도형, 미주 등) |
| `none` | `RANGE_PARAGRAPHS_DIFFER` | 끌기의 두 끝(또는 시작·끝 깃발, #74)이 다른 부모(최상위 ↔ 표 칸, 다른 칸, 글상자 ↔ 본문)나 다른 구역에 있다. 같은 부모의 다른 문단이면 문단 범위 끌기다(2026-10-04 #53) |

| `none` | `NEAREST_UNCONFIRMED` | 빈 곳인데 가장 가까운 줄의 문단을 확인하지 못했다 |
| `none` | `CELL_MISMATCH` | 셀 안 빈 곳인데 줄 후보의 글이 다른 셀의 것이다 |

- 머리말·꼬리말·각주·미주·바탕쪽: 시험 구현에서는 영역만 구별한다. 엔진 주소로 옮기는 것은 다음 단계다.
- 서로 다른 문단에 걸친 끌기 선택은 시험 구현에서 받지 않는다(같은 문단 안의 범위만).

## 4. 앵커 초안 (엔진 쪽 추가)

- `draftAnchors(doc, { sectionIndex, path, start?, end? }): AnchorDraft[]` — 엔진(`packages/hwpx-engine/src/fill/`)에 둔다. 템플릿에 그대로 넣을 수 있는 앵커([엔진 명세](engine-spec.md) 8.2)를 후보 순서대로 돌려준다.
  1. 그 자리가 누름틀 안이면 `field`
  2. 범위(`start`·`end`)가 있으면 그 범위의 `word`. 없고 `start`만 있으면 그 글자를 포함한 낱말(공백으로 나뉜 덩어리)의 `word`. `print`(대상 글, 앞뒤 문맥)를 채운다
  3. 문단의 `line`(글 지문과 해시)
  4. 구역 최상위 표의 셀 안이면 `cell`(표 서수, 행, 열)
- 누름틀은 채울 수 있는 모양만, 안쪽 것부터 낸다. 낱말은 공백과 경계 조각(객체 자리, 탭, 줄바꿈)에서 나뉜다.
- 범위가 글자 묶음을 가르면 묶음 경계로 넓힌다. 경계 조각을 포함하는 `word`는 만들지 않는다.
- 낱말·문단·셀 초안마다 기본 옵션으로 채우면 건너뛰거나 거절되는 경우 `blocked: 코드`를 붙인다(누름틀은 채울 수 없는 모양이면 초안 자체를 내지 않는다)(글자 모양이 섞인 범위 등. 채움의 판정과 같은 함수로 계산한다). 초안은 빼지 않는다. `blocked`는 템플릿의 키가 아니므로 템플릿에 넣을 때는 뗀다.
- 잘못된 주소·범위는 `FILL_DRAFT_ADDRESS`, `FILL_DRAFT_RANGE`.

**시작·끝 깃발 (#74, 2026-10-06)**

범위 선택의 두 방식(끌기·깃발, [스튜디오 명세](studio-spec.md) 4c.2) 가운데 깃발의 호스트 계약이다. 결과는 같은 두 문단을 끈 것(#53, 3절)과 같다. 검증은 [검증 기준](validation.md) 29절.

- 요청(`FlagRequest`, `src/host/types.ts`): 위치 요청과 같은 `locate`에 `{ flags: { start, end } }`를 보낸다. `start`·`end`는 각각 눌린 점 하나(`LocatePoint`: 위치와 런의 글·한계·사유, 또는 표 칸의 빈 곳 `cell`)이고 `from`·`to`와 함께 보내지 않는다. 깃발은 그 점의 **문단**까지만 쓴다(글자 순번·`trailing`·안내문은 문단을 찾는 데만 쓰인다).
- 풀기: 깃발마다 `cell`이면 `locateInCell`, 아니면 `locatePicked`(`start`)로 문단을 찾고, 끌기와 같은 함수로 범위를 낸다.
- 응답(`LocateResponse`): 같은 구역·같은 부모이면 `precision: "paragraph"`, `address`(앞 문단), `span { sectionIndex, parentPath, from, to }`(문서 순서. 끝 깃발이 시작 깃발보다 앞이면 바꿔 잡는다), `drafts`는 `range` 초안(`makeRangeAnchor`)과, 앞 문단이 제목이면 둘째로 `headingRange` 초안(`makeHeadingRangeAnchor`. 범위는 깃발과 무관하게 그 제목의 범위다). 기본 선택은 `range`(`defaultDraftIndex`). 두 깃발이 같은 문단이면 문단 하나짜리 `range`다(같은 문단 안 끌기는 글자 범위 `word`이므로 이 경우만 끌기와 다르다).
- 거절: 부모가 다르면(최상위 ↔ 표 칸, 같은 표의 다른 칸, 다른 표, 표를 담은 문단 ↔ 그 칸, 글상자 ↔ 본문·표 칸, 다른 구역) `none`·`RANGE_PARAGRAPHS_DIFFER`이고 초안이 없다. 한 깃발을 풀지 못하면 그 깃발의 사유(3절 표: `PARAGRAPH_NOT_FOUND`·`PARAGRAPH_MISMATCH`·`CELL_NOT_FOUND` 등. 시작 깃발이 먼저)다. 본문이 틀리면 400: `flags`가 객체가 아니거나 깃발이 빠졌거나 `from`·`to`와 함께 오면 `BAD_REQUEST`, 깃발에 위치도 칸도 없으면 `BAD_POSITION`, 그 밖의 위치 항목 오류는 `from`과 같다.
- 한계(3절 그대로): 머리말·꼬리말·각주·미주·바탕쪽의 글, 좌표 없는 글(쪽 번호·번호 글), 다른 문단의 런이 겹친 곳은 화면의 `pick`이 위치를 주지 않으므로(`limit: "none"`) 깃발이 될 수 없다. 묶음 개체 안 글상자·표 칸 안 도형 등 경로를 풀 수 없는 글을 깃발로 보내면 그 깃발의 사유(`none`)다.
- 화면이 할 일(Codex 몫. 뷰어·호스트는 상태를 갖지 않는다): 첫 깃발을 누르면 그 점(`LocatePoint`)을 들고 "끝을 찍으세요"를 보이며 기다린다. Esc나 취소면 첫 깃발을 버린다. `pick`이 위치를 주지 않는 점은 깃발로 받지 않고 그 영역·사유를 보인다. 둘째 깃발을 누르면 두 점을 `flags`로 보내고 응답을 끌기와 같은 상세로 보인다(`RANGE_PARAGRAPHS_DIFFER`면 이유와 함께 거절). 두 깃발 사이에 화면의 문서가 바뀌면(다시 열기·결과로 다시 그림) 첫 깃발을 버린다(점이 옛 문서의 위치다).

**블록 단독 미리보기 (#75, 2026-10-06)**

저장소 탭에서 블록을 누르면 그 블록만 그리는 요청이다([스튜디오 명세](studio-spec.md) 4c, #60 댓글 K절). 미리보기 문서를 만드는 규칙은 [엔진 명세](engine-spec.md) 8.8.18이고, 검증은 [검증 기준](validation.md) 30절.

- 함수(`src/host/preview.ts`): `previewBlock(body, loadBlock): BlockPreviewResponse`. 블록 저장소는 앱이 갖는다. `loadBlock(id)`는 `{ proto, blob }`(읽기 검사를 거친 `block-proto@1` 원형과 그 판의 조각 덩어리 바이트)을 주거나, 없으면 undefined를 준다. 호스트는 상태를 갖지 않는다.
- 요청(`BlockPreviewRequest`, `src/host/types.ts`): `{ block: "<블록 id>" }` 또는 `{ proto: <원형 JSON 객체>, blob: "<덩어리 base64>" }`. 둘을 함께 보내지 않는다. 화면은 저장한 블록을 id로 부른다(본문 방식은 저장 전 블록이나 앱 밖 블록용).
- 상한: 덩어리 `PREVIEW_MAX_BLOB` = 32 MiB(lite 블록 저장 한도와 같다). 저장소 덩어리는 바이트 길이로, 본문 덩어리는 base64를 푼 뒤의 바이트 길이로 본다(끝 패딩을 뺀 실제 크기. 글자 길이만으로 상한을 넘는 것은 풀지 않고 거절한다). base64 검사는 길이(4의 배수)·끝 패딩(`=` 2개까지)·글자 집합만 본다. 요청 본문 한도(`ShellOptions.maxBody`)는 앱이 정한다(본문 방식은 base64라 약 1.34배다).
- 응답(`BlockPreviewResponse`):

| 필드 | 뜻 |
| --- | --- |
| `hwpx` | 미리보기 HWPX 바이트(base64). 엔진의 저장 게이트를 통과한 것만 온다. 블록 최상위 문단은 구역 0의 최상위 1번부터다(0번은 글 없는 바탕 문단) |
| `sha256` | `hwpx` 바이트의 sha256(16진). 같은 블록·같은 판이면 같다 |
| `fields` | 같은 종류·같은 이름 입력 항목의 수 `{ name, kind, count }[]`(처음 나온 순서. `kind`는 `placeholder`·`clickHere`·`mailMerge`) |
| `places` | 미리보기 문서 안 입력 항목 자리(엔진 주소 `sectionIndex`·`path`, 논리 오프셋 `start`·`end`, 여러 문단 누름틀이면 `endPath`)와 쪽 위 강조 구간 `marks: MarkRange[]` |
| `warnings` | 경고 `{ code, message }[]`: 조각 가져오기 경고(`FRAG_UNIT_CONVERTED`·`FRAG_FORMAT_UNKNOWN`·`FRAG_DANGLING_SOURCE` 등)와 상속 오류 `GATE_INHERITED` |

- `marks`: 자리 구간을 위치 변환(3절)으로 rhwp 글자 순번 구간으로 옮긴 것(`markSpan`, 앵커 강조와 같은 함수). 한 문단 자리는 하나, 여러 문단 누름틀은 문단마다(시작 문단의 뒷부분, 사이 문단 전체, 끝 문단의 앞부분)다. 값 글에 줄바꿈이 있으면 줄바꿈마다 나눈다(rhwp는 줄바꿈을 글자로 그리지 않아 덮을 글이 어긋난다). 안내문 상태 누름틀은 `guide`(안내문 사각형을 덮는다), 그 밖은 `text`(덮어야 할 글. 화면은 쪽 글자 배치와 견줘 다르면 그리지 않는다)를 준다. 옮길 수 없는 문단은 빠지므로 빈 목록일 수 있다. 한계: 지금 쪽 화면(`dom/page-view.ts`)은 쪽마다 글을 견주므로 한 구간이 쪽을 넘으면 그 구간은 그려지지 않는다(긴 값 시험에서 1,408개 중 93개, 검증 기준 30절). 줄을 넘는 안내문(안내문 상태 누름틀의 안내문이 두 줄 이상으로 나뉘어 그려진 것)도 강조가 그려지지 않는다: 안내문 사각형(`rhwp/layout.ts` `guideRect`)은 안내문 글 전체와 같은 좌표 없는 런 하나를 찾으므로 줄마다 나뉜 런을 찾지 못한다(독립 검증 관측. 합성 누름틀의 한 줄 안내문 6·28자는 그려지고 여러 줄로 나뉘는 127자(첫 줄 런 46자)는 그려지지 않음을 확인했다. 아직 고치지 않았다).
- 거절(`HostError`, `{ error: { code, message } }`): 400 `BAD_REQUEST`(본문이 객체가 아님, `block`이 문자열이 아니거나 비었거나 200자를 넘음, `block`과 `proto`·`blob`을 함께 보냄, `proto`가 객체가 아니거나 `blob`이 문자열이 아님), 400 `BAD_BLOB`(base64가 아님), 404 `BLOCK_NOT_FOUND`(저장소에 없음), 413 `BLOCK_TOO_LARGE`(상한 초과), 400 엔진 코드(원형 읽기 거절 `TPL_FIELD`·`TPL_ID` 등), 422 엔진 코드(미리보기를 만들 수 없음: `TPL_FRAGMENT_MISSING`·`FRAG_SCHEMA`·`GATE_NEW_ERRORS` 등). 거절이면 바이트를 주지 않는다.
- 화면이 할 일(Codex 몫. 뷰어·호스트에는 구현하지 않았다): 저장소 목록에서 블록을 누르면 `{ block }`을 보내고 `hwpx`를 다른 문서와 같은 뷰어(rhwp)로 연다. `places[].marks`를 쪽 위에 덧그려 입력 항목 자리를 강조하고, `fields`로 "입력 n"과 이름별 수를 보인다(n을 자리 수로 셀지 이름 수로 셀지는 화면이 정한다). `warnings`는 쉬운 말로 보인다. 거절이면 이유를 보이고 원문 일부 보기로 대신한다. 첫 줄의 빈 바탕 문단은 블록의 일부가 아니다. 미리보기는 표시용이다(저장·편집 결과를 호스트로 돌려보내지 않는다). 쪽 설정은 바탕의 A4이므로 원본과 줄 나뉨이 다를 수 있다(엔진 명세 8.8.18 한계).

## 5. 시험 구현의 화면

- 문서 고르기(저장소의 시험 문서 목록, 또는 파일 선택으로 로컬 파일 올리기).
- 쪽을 세로로 이어 그린다(SVG). 배율 50~200%. 첫 쪽은 바로 그리고 나머지는 화면에 보일 때 그린다(창이 가려져 그리기 프레임이 돌지 않아도 첫 쪽은 준비된다).
- 클릭: 영역(본문·표 셀·글상자·머리말·꼬리말·각주)과 엔진 주소, 정밀도, 앵커 초안 목록을 옆 패널에 보여 준다. 끌기: 같은 문단 안의 범위. 막힌 초안은 표시하고 기본으로 고르지 않는다. 문단 초안은 그것이 유일한 초안일 때만 기본으로 고른다(문단 채움은 문단 글 전체를 바꾼다).
- 강조 표시: 고른 앵커의 자리, 문서의 누름틀과 `{{}}` 자리(엔진의 후보 목록)를 쪽 위에 덧그린다.
- 채우기: 고른 앵커와 값으로 엔진의 `generate`를 호출한다(저장 게이트 포함). 성공하면 결과 바이트로 다시 그리고, 결과 파일을 내려받을 수 있다. 실패하면 보고서의 오류를 보여 준다. 적용된 곳이 0이면 실패다(`FILL_NOTHING_APPLIED`와 건너뜀 사유).
- 호스트가 문서 바이트를 갖는다. 브라우저는 표시용 바이트를 받아 rhwp에 넣을 뿐이고, 편집 결과를 호스트로 돌려보내지 않는다.
- 마지막 클릭의 응답만 반영한다. 응답을 기다리는 동안에는 이전 초안을 비우고 채우기를 막는다. 채우기와 문서 교체는 기다리던 응답을 버린다.
- 문서를 다시 열면 이전 세션을 닫는다. 끌기 미리보기는 그리기 프레임당 한 번만 계산하고, 끌기 중 화면이 교체되면 정리한다.
- 호스트 API의 오류는 `{ error: { code, message } }` JSON이다. 채우기 요청의 앵커 `id`는 호스트가 붙인다(요청의 `id`는 무시).

## 6. 수용 조건

| ID | 조건 |
| --- | --- |
| V1 | Node에서 rhwp로 저장소의 시험 문서 전부와 실제 문서 표본을 연다. 못 여는 문서는 사유별 수량으로 보고한다 |
| V2 | **전수 대조**: 연 문서의 모든 쪽에서, 문서 좌표가 있는 런마다 엔진 주소로 옮기고 런의 글이 엔진 논리 텍스트의 그 자리와 같은지 본다. **클릭 경로 대조**: 글자 표본을 실제 화면 경로로 눌러, 돌아온 오프셋의 엔진 글자가 누른 글자와 같은지 대응표를 쓰지 않는 방법으로 본다(좌표 없는 글과 빈 곳 포함, 채운 뒤 다시 그린 문서 포함). 시험 문서는 본문·표 셀·중첩 표·글상자 모두 100%. 실제 문서는 일치율과 불일치 사유별 수량을 보고하고, 불일치가 조용히 `char` 정밀도로 나가는 경우는 0 |
| V3 | 왕복: 엔진 주소 → rhwp 위치 → 화면 사각형 → 그 사각형 안을 누름 → 같은 위치. 시험 문서의 글자 표본에서 맞거나, 사유와 함께 `char`가 아니어야 한다(겹친 자리를 빼지 않는다) |
| V4 | 머리말·꼬리말·각주·바탕쪽을 누르면 본문 위치가 아니라 영역으로 보고된다. 쪽 번호 같은 좌표 없는 글은 위치 없음이다 |
| V5 | 브라우저: 시험 문서를 그리고, 낱말을 눌러 나온 앵커로 값을 채우면 다시 그린 화면의 그 자리에 값이 보인다. 누름틀, `{{}}`, 일반 낱말, 표 셀 각 1건 이상. 결과 파일은 저장 게이트를 통과하고 한컴에서 열린다 |
| V6 | 배율 50%·100%·150%에서 클릭 위치가 같은 글자를 가리킨다. 강조 표시가 글자 위에 맞는다 |
| V7 | 오프라인: 화면이 외부 주소를 요청하지 않는다(네트워크 요청 목록으로 확인) |
| V8 | 수치 보고: 큰 문서의 열기·쪽 그리기·글자 배치·클릭 위치 시간, rhwp 쪽 수와 한컴 쪽 수의 차이(시험 문서) |

## 7. 시험 구현 결과 (2026-10-02)

수용 조건 V1~V8을 확인했다. 수치와 독립 검증 경과는 [검증 기준](validation.md) 12절에 둔다.

- 패치 없는 npm 배포본으로 본문·표 셀·중첩 표·글상자의 클릭 위치를 엔진 주소로 옮길 수 있다.
- rhwp의 클릭 위치 함수는 글자 위치의 근거로 쓸 수 없다(첫 구현은 이것을 믿어 클릭의 0.76%가 다른 자리를 가리켰다). 포인터 아래에 그려진 글이 근거다.
- 옮기지 못하는 글: 묶음 개체 안 글상자, 표 셀 안 도형의 글, 쪽 수준에 그려진 표, 미주. 틀린 위치를 내지 않고 `none`으로 답한다.
- 빈 곳의 `none` 비율(실제 문서 175건, 코드 리뷰 반영 뒤): 본문 약 20%, 표 셀 약 8.5%, 중첩 셀 약 5%, 글상자 약 29%. 보수적으로 막은 것이다.
- 글이 전혀 없는 표의 빈 셀도 옮긴다(셀의 첫 문단).
