# 사용 안내 — 빠른 생성

- 작성일: 2026-10-03 (갱신 2026-10-05: lite 앱, 2판 템플릿 예시)
- 이 문서가 소유하는 주제: 비전문가가 빠른 생성 화면을 쓰는 방법(한컴에서 자리 적기, 데이터 만들기, 결과 읽기)과 2판 템플릿 예시를 명령줄로 해 보는 순서(8절)
- 소유하지 않는 주제: 화면·API의 계약은 [스튜디오 명세](studio-spec.md) 4a절, 엔진의 규칙은 [엔진 명세](engine-spec.md)

한컴에서 `{{키}}`나 누름틀을 적어 둔 문서(.hwpx)와 데이터(.json)를 올리면, 데이터의 값으로 자리를 채운 문서를 건마다 하나씩 만들어 줍니다. 원본 문서는 고치지 않습니다.

처음이면 `examples/quick/` 폴더의 예시 서식·데이터로 먼저 해 보세요. 고쳐 가며 시험하는 순서는 그 폴더의 [README](../examples/quick/README.md)에 있습니다. 조항을 바꿔 넣는 템플릿은 8절과 `examples/template-v2/`를 보세요.

## 1. 켜는 방법

터미널에서 저장소 폴더로 가서 아래를 입력하고, 브라우저에서 `http://127.0.0.1:4318`을 엽니다. 이 주소는 내 컴퓨터 안에서만 열립니다.

```
npm run start:lite
```

- 첫 화면(`/`)은 **템플릿 준비 · 빠른 생성**입니다. 2~6절이 이 화면 이야기입니다.
- 위쪽 **저장한 템플릿으로 생성**(`/template`)은 lite에 저장해 둔 템플릿으로 만드는 화면입니다.
- 포트를 바꾸려면 PowerShell에서 `$env:PORT=4319`를 입력한 뒤 켭니다. 끄려면 터미널에서 Ctrl+C를 누릅니다.

## 2. 한컴에서 자리 만들기

자리는 두 가지로 만들 수 있고, 한 문서에 섞어 써도 됩니다.

### 2-1. `{{키}}` 적기

채울 곳에 `{{` 와 `}}` 사이에 키 이름을 적습니다. 예: `사업명: {{project.name}}`

- **`{{키}}` 전체를 같은 글자 모양으로, 한 번에 이어서 입력하세요.** 입력하는 도중에 글꼴·크기·굵기·색을 바꾸면 프로그램이 `{{키}}`를 한 덩어리로 보지 못해 그 자리를 건너뜁니다(보고서에 "글자 모양이 중간에 바뀌어 있어 건너뛰었습니다"라고 나옵니다). 이미 그렇게 된 자리는 지우고 다시 입력하면 됩니다.
- `{{`와 `}}` 사이에 탭·줄바꿈·그림을 넣으면 자리로 알아보지 못할 수 있습니다. 화면 왼쪽 **문서의 자리**의 "{{키}}" 목록에 내가 적은 자리가 모두 나오는지 꼭 확인하세요. 목록에 없으면 인식하지 못한 것입니다.
- 키 이름에는 글자(한글 포함)·숫자·`_`·`-`만 쓸 수 있습니다. 공백은 쓸 수 없습니다. 점(`.`)은 "안쪽 항목"을 뜻합니다: `{{project.name}}`은 데이터의 `project` 안의 `name` 값을 가져옵니다.
- `{{ project.name }}`처럼 괄호 안쪽에 공백을 넣어도 됩니다.
- 표 안, 글상자 안, 머리말·꼬리말·각주 안에 적은 `{{키}}`도 채워집니다.

### 2-2. 누름틀 넣기

누름틀은 한컴이 "여기에 입력하세요" 하고 안내문을 보여 주는 입력 칸입니다. 이 프로그램은 **누름틀의 이름을 데이터의 키로 씁니다.**

- 한컴에서 메뉴 **입력 → 필드 입력**(단축키 Ctrl+K, E)을 열고 **누름틀** 탭에서 안내문과 이름을 적어 넣는 방식입니다. 한컴 버전에 따라 메뉴 이름이나 위치가 조금 다를 수 있습니다. 못 찾겠으면 한컴 도움말에서 "누름틀"을 찾아 보세요.
- **누름틀 이름이 데이터의 키와 같아야 합니다.** 이름이 `성명`이면 데이터의 `성명` 값이, `applicant.name`이면 `applicant` 안의 `name` 값이 들어갑니다. 이름의 규칙은 `{{키}}`와 같습니다(글자·숫자·`_`·`-`, 점은 안쪽 항목). **이름에 공백·점·괄호가 잘못 들어 있어 이 꼴이 아닌 누름틀은 채우지 않고 그대로 두며**(건너뜀), 보고서에 "누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않았다"고 나옵니다. 화면의 대조표에도 "데이터 경로로 쓸 수 없는 이름"으로 표시됩니다.
- 같은 이름의 누름틀이 문서에 여러 개 있으면 모두 같은 값으로 채웁니다.
- **여러 문단에 걸친 누름틀**(누름틀 안에서 Enter를 친 서식)은 한컴과 같은 방식으로 채웁니다: 첫 문단에 값이 들어가고, 그 사이에 있던 문단(표가 있으면 표도)은 지워지며, 끝 표식 뒤의 글은 첫 문단에 이어 붙습니다. **문서의 자리**에 "N곳은 문단 합침"으로 미리 알리고, 결과의 "알림"에도 적습니다. 사이 문단이 지워지는 것이 싫으면 한컴에서 누름틀을 한 문단 안으로 다시 만드세요.
- 줄바꿈이 든 값으로 채운 결과 파일을 다시 서식으로 올려도 그 누름틀은 다시 채워집니다(옛 값이 통째로 바뀝니다).
- 여러 문단에 걸친 누름틀이라도 사이 문단에 구역 설정이 있거나 다른 누름틀과 엇갈려 있으면 채우지 않습니다. **문서의 자리**에 "채우지 못함: 여러 문단 경계 때문에 채울 수 없음"과 사유로 미리 표시됩니다.
- 안에 그림·표가 들어 있거나, 표 칸 안에서 시작해 칸 밖에서 끝나거나, 끝 표식이 없는 누름틀은 값을 넣을 수 없어 그대로 두고 건너뜁니다. **문서의 자리**에 "채우지 못함"과 모양으로, 대조표에 "채울 수 없는 누름틀"로 미리 표시되고, 보고서의 "건너뜀"에도 나옵니다.
- **메일 머지 필드**(한컴 메일 머지용 필드. 키가 들어 있음)는 누름틀처럼 채웁니다: 필드의 키를 데이터 키로 써서 표시 글을 값으로 바꾸고 필드는 그대로 둡니다. 키에 공백·괄호가 있으면 채우지 않고 알립니다. 메일 머지를 더 쓰지 않을 서식은 명령줄 `compile --merge-fields to-placeholder`(또는 `to-field`)로 `{{키}}`나 누름틀로 한 번에 바꿀 수 있습니다.
- 한컴의 다른 필드(책갈피, 날짜, 계산식, 키 없는 메일 머지 등)는 자리가 아니라서 건드리지 않고, **문서의 자리**에도 나오지 않습니다.
- 채울 수 있는 자리가 문서에 하나도 없거나, 가진 자리가 전부 건너뛰어지거나 "원래 글 유지"여서 **채운 자리가 하나도 없으면 그 건은 실패**입니다(원본과 같은 파일을 만들지 않습니다).

## 3. 데이터(JSON) 만들기

JSON은 데이터를 적는 약속된 글 형식입니다. 메모장 같은 편집기로 만들고 **UTF-8**로 저장하세요. 엑셀·CSV 파일은 올릴 수 없습니다.

**한 건**: 중괄호 하나. 문서의 `{{project.name}}`은 아래의 "알파 사업"으로 채워집니다.

```
{ "project": { "name": "알파 사업", "start": "2026-01-01" }, "manager": "홍길동" }
```

**여러 건**: 대괄호 안에 건마다 중괄호 하나. 건이 N개면 결과 파일도 N개입니다(한 번에 1000건까지).

```
[
  { "project": { "name": "알파 사업" }, "manager": "홍길동" },
  { "project": { "name": "베타 사업" }, "manager": "김철수" }
]
```

**묶음 형식**: `schema`를 적고 `data`에 위의 한 건 또는 여러 건을 넣습니다. `derived`는 `data`에 없는(또는 null인) 키를 보충하는 값이며 모든 건이 함께 씁니다.

```
{ "schema": "hwpx-studio/dataset@1", "data": [ { "manager": "홍길동" }, { "manager": "김철수" } ], "derived": { "회사": "예시 주식회사" } }
```

값으로 쓸 수 있는 것은 글자, 숫자, true/false입니다(숫자·true/false는 글자로 바뀌어 들어갑니다). 중괄호나 대괄호로 된 값(객체·배열)은 자리에 넣을 수 없습니다. 값이 `null`이거나 키가 없으면 "데이터 없음 / null"입니다. 여러 건의 데이터 항목 하나가 객체가 아니면 그 건만 실패합니다.

### 줄바꿈이 있는 값

JSON에서는 줄바꿈을 `\n`으로 적습니다. 예: `"주소": "서울시 가구\n나동 1번지"`. **줄바꿈이 든 값은 그대로 들어갑니다.** 값의 줄바꿈은 문서 안에서 같은 문단 안의 줄바꿈이 되고(문단이 나뉘지 않습니다), 탭(`\t`)은 탭이 됩니다. 윈도에서 만든 줄바꿈(`\r\n`)도 줄바꿈 하나로 들어갑니다. 대조표에는 "데이터 있음" 뒤에 "줄바꿈/탭 유지"가 붙고, 결과의 "알림" 열에는 "값에 줄바꿈·탭이 있어 … 넣었습니다"라고 알려 주기만 하고, 오류나 건너뜀이 아닙니다.

글에 넣을 수 없는 제어 문자(보이지 않는 특수 문자)가 값에 있으면 그 건이 실패합니다. 다른 프로그램에서 복사한 글에 숨어 있는 경우가 있습니다. 대조표에는 "값 문자 차단"으로 나옵니다.

## 4. 화면에서 하는 일

첫 화면(`/`)은 왼쪽·가운데·오른쪽 세 칸입니다.

1. 왼쪽 **템플릿 준비**에서 **HWPX 문서 올리기**로 .hwpx를 고릅니다. 가운데 **원본 문서**에 문서가 보이고(읽기 전용), 왼쪽 **문서의 자리**에 찾은 누름틀·`{{키}}`·빈칸 후보(라벨 옆 빈 칸, `라벨:` 뒤 빈 곳, 빈칸 표시)가 나옵니다. 빈칸 후보는 **알려 주기만 하고 채우지 않습니다.**
2. 오른쪽 **JSON 데이터**에서 **JSON 데이터 올리기**로 .json을 고릅니다. 건수가 나오고, **데이터 경로 목록**에서 내 데이터의 키를 볼 수 있습니다.
3. 오른쪽 **자리 · 데이터 대조표**에서 자리마다 데이터와 맞는지 봅니다. 여러 건이면 "맞음 N / 누락 M"으로 건수가 함께 나옵니다.
   - **데이터 있음**: 채울 수 있습니다. "줄바꿈/탭 유지"가 붙으면 줄바꿈·탭이 든 값이며 문제가 아닙니다.
   - **데이터 없음 / null**: 데이터에 그 키가 없거나 값이 null입니다. 철자나 대소문자를 보세요.
   - **객체·배열**: 값이 중괄호·대괄호로 되어 있습니다. 안쪽 항목(`키.이름`)을 쓰세요.
   - **값 문자 차단**: 글에 넣을 수 없는 제어 문자가 있어 그 건은 실패합니다(3절).
   - **데이터 경로로 쓸 수 없는 이름**: 누름틀 이름을 고쳐야 합니다(2-2).
   - **채울 수 없는 필드**: 괄호 안의 사유를 보고 한컴에서 한 문단 안의 글만 담는 누름틀로 다시 만듭니다.
4. (필요할 때) `{{키}}`·누름틀이 없는 곳을 채우려면 가운데 문서에서 클릭하거나 끌어 고른 뒤, 오른쪽 **선택한 위치**에서 **연결할 데이터 경로**를 고르고 **선택한 자리 연결**을 누릅니다. 왼쪽 **명시적으로 연결한 자리**에 쌓입니다. 이 연결은 지금 작업에만 쓰이고 저장되지 않습니다.
5. 오른쪽 **생성 설정**의 **값이 없을 때**를 고릅니다.
   - **해당 건을 실패로 처리**(기본): 그 건은 만들지 않습니다. 빠뜨린 값을 놓치지 않으려면 이 방식이 안전합니다.
   - **원래 글 유지**: 그 자리의 글(`{{키}}` 또는 누름틀 안내문)을 남기고 나머지만 채웁니다. 채울 자리가 하나도 없으면 그 건은 실패합니다.
   - **빈 글로 채우기**: 그 자리를 비웁니다.
6. **연결 확인 후 HWPX 생성**을 누르면 가운데 **생성 결과 · 알림** 표에 건마다 결과가 나옵니다. 한 건이 실패해도 나머지는 만듭니다. **내려받기**로 파일을 받고, **미리보기**로 화면에서 읽기만 할 수 있습니다.

채운 글이 문서에서 어떻게 보이는지는 한컴에서 직접 열어 확인해 주세요. 이상하게 보이면 어느 문서와 어느 데이터인지 알려 주세요.

### 메일머지 서식 채우기

한컴 메일머지 필드로 자리를 만든 서식도 같은 화면(`/quick`)에서 채웁니다. 시험용 예시: `examples/quick/template-mailmerge.hwpx`와 `data-mailmerge.json`.

1. 서식을 올리면 **문서의 자리**에 "누름틀·메일머지 키 N개 · M곳 (메일머지 a · 누름틀 b)"와 키마다 "메일머지 키 · n곳"이 나옵니다. 필드 안에 적힌 `{{키}}`는 그 필드가 채우므로 `{{키}}` 목록에 따로 세지 않습니다.
2. JSON을 올리면 대조표 위에 "데이터와 맞는 자리 N개 키 · M곳 (메일머지 …)"과 데이터 없음·이름 규칙 밖 키 수가 나옵니다. JSON의 키는 필드의 키와 같아야 합니다.
3. 생성합니다. 키에 공백·괄호가 있는 필드는 채우지 않고 건너뜁니다. 그런 건은 결과가 "일부 채움 · N곳 채움 · M곳 건너뜀"(노란 글)이고 위 상태줄에도 "일부 자리를 건너뛴 건"이 적힙니다. **건너뜀** 칸의 `[메일머지 "키"]`가 어느 필드인지 알려 줍니다.
4. 건너뛴 필드도 채우려면 한컴에서 그 필드의 키를 글자·숫자·`_`·`-`로 고쳐 다시 올립니다. 작업창(`/`)의 추천 목록에도 메일머지 필드가 "입력 · 메일머지"로 나오고, 이름 규칙 밖 키는 노란 점선 밑줄로 보입니다.

## 5. 결과는 어디에 저장되나

- lite 첫 화면은 결과를 폴더에 저장하지 않고 **내려받기**로만 줍니다(작업 공간 폴더에 저장하기·폴더 열기는 아직 옮기지 않았습니다). 내려받은 파일은 브라우저의 내려받기 폴더에 생깁니다.
- 파일 이름은 `원본이름-001.hwpx`, `원본이름-002.hwpx`처럼 건 번호(1부터)가 붙습니다. 한 건이어도 `-001`이 붙습니다. 이름에 쓸 수 없는 글자는 `_`로 바뀝니다. 실패한 건은 파일이 없습니다.
- **올린 원본 문서와 데이터는 디스크에 저장하지 않고**(프로그램이 켜져 있는 동안만 메모리에 있고, 끄면 사라집니다), 원본 파일도 고치지 않습니다.

## 6. 문제가 났을 때 보고서의 어느 줄을 볼까

생성 뒤 가운데 **생성 결과 · 알림** 표에 건마다 한 줄이 나옵니다.

- **결과**: 성공/실패.
- **채운 자리**: 그 건에서 값을 넣은 곳의 수입니다. 같은 키가 여러 곳이면 곳마다 셉니다.
- **건너뜀**: 채우지 않고 넘어간 자리와 이유입니다. 건너뛰어도 그 건은 성공일 수 있으니 꼭 읽어 보세요.
- **오류**: 실패한 이유입니다(붉은 글).
- **알림**: 실패도 건너뜀도 아닌 참고 사항입니다(예: 줄바꿈이 든 값을 넣었음).

건너뜀·알림 줄은 `[어느 자리] 쉬운 설명 코드` 모양이고, 오류 줄은 `쉬운 설명 코드`이며 어느 자리인지는 설명 안에 적힙니다. 코드(`DATA_MISSING` 같은 영문)는 사람에게 문의할 때 알려 주면 빨리 찾을 수 있습니다. 자주 만나는 줄:

| 줄에 나오는 말 | 하면 되는 일 |
| --- | --- |
| 데이터에 이 키의 값이 없습니다 | 데이터에 키를 더하거나, 철자를 맞추거나, 누락 정책을 바꿉니다 |
| 글자 모양이 중간에 바뀌어 있어 건너뛰었습니다 | 한컴에서 그 `{{키}}`를 지우고 같은 글자 모양으로 한 번에 다시 입력합니다 |
| 사이에 탭·줄바꿈·그림이 끼어 있어 건너뛰었습니다 | 한컴에서 `{{키}}`를 처음부터 끝까지 이어서 다시 입력합니다 |
| 값에 글에 넣을 수 없는 제어 문자가 들어 있습니다 | 데이터에서 그 값의 보이지 않는 문자를 지웁니다 |
| 객체나 배열이어서 자리에 넣을 수 없습니다 | 안쪽 항목의 키(`키.이름`)를 문서에 적습니다 |
| 이 누름틀은 안에 그림·표가 있거나, 표 칸 경계를 넘거나, 끝 표식이 없거나, 사이 문단에 구역 설정이 있거나, 다른 누름틀과 엇갈려 값을 넣을 수 없어 그대로 두었습니다 | 한컴에서 그 누름틀을 한 문단 안의 글만 담도록 다시 만듭니다 |
| 이 누름틀은 여러 문단에 걸쳐 있어서 첫 문단에 값을 넣고 그 사이 문단을 지웠습니다 | 알림입니다. 결과를 한컴에서 열어 사라진 문단이 없는지 확인합니다 |
| 누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 누름틀 이름을 글자·숫자·`_`·`-`(안쪽 항목은 점)로 고칩니다 |
| 메일 머지 필드의 키가 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 그 필드의 키를 고치거나, `compile --merge-fields`로 바꾼 뒤 `{{키}}`를 고칩니다 |
| 채운 자리가 하나도 없어 결과를 만들지 않았습니다 | 문서의 `{{키}}`·누름틀 이름과 데이터의 키가 맞는지 비교합니다. 누름틀 이름이 키와 같아야 합니다 |
| 이 파일은 .hwpx 문서가 아닙니다 / 옛 형식(.hwp)입니다 | 한컴에서 .hwpx로 다른 이름으로 저장해 다시 올립니다 |
| …새 오류가 생겨, 안전을 위해 결과를 만들지 않았습니다 | 프로그램이 안전 검사에서 멈춘 것입니다. 문서와 데이터를 알려 주세요 |

## 7. 지금의 한계

- **빠른 생성에서는 키에 공백·점이 들어 있으면 쓸 수 없습니다.** 엑셀 머리글처럼 "회사 이름", "금액(원)", "a.b"가 키인 데이터는 키 이름을 글자·숫자·`_`·`-`로 바꿔야 합니다(점은 안쪽 항목으로만 쓰입니다). 2판 템플릿(8절)은 연결에 머리글을 그대로 적을 수 있습니다.
- **그림·도형 자리**: 그림 자체를 바꾸거나 그림·도형을 채우는 기능은 없습니다. 글상자·표·머리말·꼬리말·각주 안의 글은 채워집니다.
- **후보 자리**(빈칸 표시 등)는 알려 주기만 하고 채우지 않습니다.
- 여러 문단에 걸친 누름틀을 채우면 사이 문단이 지워집니다(한컴과 같은 동작). 지워지면 안 되는 내용이 사이에 있으면 누름틀을 한 문단 안으로 다시 만드세요.
- 메일 머지 필드도 누름틀처럼 채웁니다(2-2). 키에 공백·괄호가 있는 필드는 빠른 생성에서는 채우지 않고 알립니다.
- "원래 글 유지"로 남겨 둔 자리는 보고서에 따로 적히지 않습니다. 대조표의 "데이터 없음 / null"로 어느 키가 없었는지 확인하세요.
- 빠른 생성은 값을 데이터에 보이는 그대로 넣습니다. 금액에 쉼표와 `원`을 붙이려면 2판 템플릿의 금액 형식(`money`, 8절)을 씁니다. 날짜 형식은 아직 없습니다.
- 여러 문단을 한 덩어리로 바꿔 넣는 범위 지정은 명령줄(8절)과 뷰어의 끌기 초안으로 할 수 있습니다. 화면에서 지정해 저장하는 것은 다음 단계입니다.
- 한 번에 1000건까지입니다. 화면이 한 번에 보내는 양이 32MB까지라서 .hwpx는 약 24MB, .json은 약 32MB까지 올릴 수 있습니다. 건이 많거나 문서가 크면 만드는 동안 화면이 잠시 멈춥니다.
- 만든 결과 파일에는 원본의 미리보기 글·그림과 작성자 정보가 그대로 남아 있을 수 있습니다. 밖으로 보내기 전에 한컴에서 확인하세요(정리 기능은 아직 없습니다. #15).
- 화면에서 클릭으로 연결한 자리는 지금 작업에만 쓰이고 저장되지 않습니다. 문서 내용을 고치려면 한컴에서 고친 뒤 다시 올립니다.

## 8. 조항을 바꿔 넣는 템플릿(2판) — 명령줄로 먼저

공고서의 한 조항(예: 참가 자격)을 금액이나 이번 건의 선택에 따라 다른 글로 통째로 바꿔 넣는 방법입니다. 화면은 다음 단계(Codex)이고, 지금은 명령줄로 합니다. 예시 파일과 고쳐 볼 거리는 [`examples/template-v2/README.md`](../examples/template-v2/README.md)에 있습니다.

말뜻:

- **값**: 이름과 형식을 가진 데이터 한 칸입니다. 형식이 금액(`money`)이면 `150000000`이 `150,000,000원`으로 들어갑니다.
- **자리**: 문서의 `{{키}}`처럼 값이 들어갈 곳입니다. 어느 값을 받는지 템플릿에 적어 둡니다.
- **슬롯**: 문서에서 내용을 통째로 바꾸는 곳입니다. 번호 제목 하나부터 다음 같은 단계 제목 앞까지(제목 범위), 또는 정한 문단들(범위)로 잡습니다.
- **블록**: 슬롯에 들어갈 내용 한 가지입니다. 글이거나, 다른 문서에서 떠 온 조각(표 포함)입니다. 블록마다 고르는 조건을 둘 수 있습니다.
- **이번 건**: 이 건에서만 쓰는 선택과 고친 값입니다(`case.json`). 템플릿과 데이터는 바꾸지 않습니다.

순서(저장소 폴더에서):

1. 제목 보기: `node apps/cli/src/main.ts headings examples/template-v2/notice.hwpx`. 프로그램이 알아본 번호 제목과 단계가 나옵니다. 슬롯은 이 제목으로 잡습니다.
2. 만들기: 아래를 입력하면 `result.hwpx`와 보고서 `report.json`이 생깁니다. 다시 만들 때는 끝에 `--overwrite`를 붙입니다.

```
node apps/cli/src/main.ts fill examples/template-v2/notice.hwpx --template examples/template-v2/template.json --case examples/template-v2/case.json --blobs examples/template-v2/blobs --data examples/template-v2/data.json -o result.hwpx --report report.json
```

3. 화면에 `슬롯 s1: b1 (default)`, `슬롯 s2: b4 (manual)`처럼 슬롯마다 고른 블록이 나옵니다. `result.hwpx`를 한컴에서 열어 봅니다.

블록을 고르는 법:

- **금액 조건**: 예시의 참가 자격 슬롯은 추정가격이 1억 원 이상이면 b1, 10억 원 이상이면 표가 든 b3(우선순위가 높음), 둘 다 아니면 조건 없는 b2를 넣습니다. `data.json`의 금액만 바꿔도 들어가는 조항이 바뀝니다. 금액은 쉼표 없는 숫자로 적습니다.
- **수동 선택**: 조건 없는 블록이 둘 이상인 슬롯(예시의 제출 서류)은 `case.json`의 `selections`에서 직접 고릅니다. 고르지 않으면 `SEL_UNDECIDED`로 멈추고 결과를 만들지 않습니다. 고른 블록은 데이터가 바뀌어도 그대로입니다.

결과 보고서(`report.json`)에서 볼 곳:

- `report.selections`: 슬롯마다 고른 블록과 이유(`default` 조건이 참, `fallback` 조건 없는 블록, `manual` 직접 고름, `undecided`·`recheck` 막힘).
- `report.moves`: 블록을 넣으면서 문단 번호가 얼마나 움직였는지입니다.
- `report.dropped`: 블록이 덮어서 빠진 자리입니다(실패 아님).
- `report.issues`: 오류의 코드와 설명입니다. 자주 만나는 코드와 할 일은 예시 README의 표에 있습니다.

원본 `notice.hwpx`를 한컴에서 고쳐 저장하면 템플릿이 기억하는 원본과 달라져 `TPL_SOURCE_MISMATCH`로 막힙니다. 예시에서는 `node tools/examples/make-template-v2.ts --refresh`로 템플릿을 새 원본에 맞춥니다.
