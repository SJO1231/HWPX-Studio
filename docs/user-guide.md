# 사용 안내 — 빠른 생성

- 작성일: 2026-10-03 (갱신 2026-10-05: lite 앱, 2판 템플릿 예시. 2026-10-07: 주소 `/quick`, 남은 자리 알림·차단, Helper JSON. 2026-10-08: 작업창 표 보기 9절)
- 이 문서가 소유하는 주제: 비전문가가 빠른 생성 화면을 쓰는 방법(한컴에서 자리 적기, 데이터 만들기, 결과 읽기), 2판 템플릿 예시를 명령줄로 해 보는 순서(8절), 작업창 표 보기로 입력 항목에 이름 붙이기(9절)
- 소유하지 않는 주제: 화면·API의 계약은 [스튜디오 명세](studio-spec.md) 4a절, 엔진의 규칙은 [엔진 명세](engine-spec.md)

한컴에서 `{{키}}`나 누름틀을 적어 둔 문서(.hwpx)와 데이터(.json)를 올리면, 데이터의 값으로 자리를 채운 문서를 건마다 하나씩 만들어 줍니다. 원본 문서는 고치지 않습니다.

처음이면 `examples/quick/` 폴더의 예시 서식·데이터로 먼저 해 보세요. 고쳐 가며 시험하는 순서는 그 폴더의 [README](../examples/quick/README.md)에 있습니다. 조항을 바꿔 넣는 템플릿은 8절과 `examples/template-v2/`를 보세요.

## 2. 한컴에서 자리 만들기

자리는 두 가지로 만들 수 있고, 한 문서에 섞어 써도 됩니다.

### 2-1. `{{키}}` 적기

채울 곳에 `{{` 와 `}}` 사이에 키 이름을 적습니다. 예: `사업명: {{project.name}}`

- **`{{키}}` 전체를 같은 글자 모양으로, 한 번에 이어서 입력하세요.** 입력하는 도중에 글꼴·크기·굵기·색을 바꾸면 프로그램이 `{{키}}`를 한 덩어리로 보지 못해 그 자리를 건너뜁니다(보고서에 "글자 모양이 중간에 바뀌어 있어 건너뛰었습니다"라고 나옵니다). 이미 그렇게 된 자리는 지우고 다시 입력하면 됩니다.
- `{{`와 `}}` 사이에 탭·줄바꿈·그림을 넣으면 자리로 알아보지 못할 수 있습니다. 화면 왼쪽 **문서의 자리**의 "{{키}}" 목록에 내가 적은 자리가 모두 나오는지 꼭 확인하세요. 목록에 없으면 인식하지 못한 것입니다.
- 키 이름에는 글자(한글 포함)·숫자·`_`·`-`만 쓸 수 있습니다. 공백은 쓸 수 없습니다. 점(`.`)은 "안쪽 항목"을 뜻합니다: `{{project.name}}`은 데이터의 `project` 안의 `name` 값을 가져옵니다.
- `{{ project.name }}`처럼 괄호 안쪽에 공백을 넣어도 됩니다.
- 표 안, 글상자 안, 머리말·꼬리말·각주 안에 적은 `{{키}}`도 채워집니다.

### 2-2. 누름틀 넣기

누름틀은 한컴이 "여기에 입력하세요" 하고 안내문을 보여 주는 입력 칸입니다. 이 프로그램은 **누름틀의 이름을 데이터의 키로 씁니다.**

- 한컴에서 메뉴 **입력 → 필드 입력**(단축키 Ctrl+K, E)을 열고 **누름틀** 탭에서 안내문과 이름을 적어 넣는 방식입니다. 한컴 버전에 따라 메뉴 이름이나 위치가 조금 다를 수 있습니다. 못 찾겠으면 한컴 도움말에서 "누름틀"을 찾아 보세요.
- **누름틀 이름이 데이터의 키와 같아야 합니다.** 이름이 `성명`이면 데이터의 `성명` 값이, `applicant.name`이면 `applicant` 안의 `name` 값이 들어갑니다. 이름의 규칙은 `{{키}}`와 같습니다(글자·숫자·`_`·`-`, 점은 안쪽 항목). **이름에 공백·점·괄호가 잘못 들어 있어 이 꼴이 아닌 누름틀은 채우지 않고 그대로 두며**(건너뜀), 보고서에 "누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않았다"고 나옵니다. 화면의 대조표에도 "데이터 경로로 쓸 수 없는 이름"으로 표시됩니다.
- 같은 이름의 누름틀이 문서에 여러 개 있으면 모두 같은 값으로 채웁니다.
- **여러 문단에 걸친 누름틀**(누름틀 안에서 Enter를 친 서식)은 한컴과 같은 방식으로 채웁니다: 첫 문단에 값이 들어가고, 그 사이에 있던 문단(표가 있으면 표도)은 지워지며, 끝 표식 뒤의 글은 첫 문단에 이어 붙습니다. **문서의 자리**에 "N곳은 문단 합침"으로 미리 알리고, 결과의 "알림"에도 적습니다. 사이 문단이 지워지는 것이 싫으면 한컴에서 누름틀을 한 문단 안으로 다시 만드세요.
- 줄바꿈이 든 값으로 채운 결과 파일을 다시 서식으로 올려도 그 누름틀은 다시 채워집니다(옛 값이 통째로 바뀝니다).
- 여러 문단에 걸친 누름틀이라도 사이 문단에 구역 설정이 있거나 다른 누름틀과 엇갈려 있으면 채우지 않습니다. **문서의 자리**에 "채우지 못함: 여러 문단 경계 때문에 채울 수 없음"과 사유로 미리 표시됩니다.
- 안에 그림·표가 들어 있거나, 표 칸 안에서 시작해 칸 밖에서 끝나거나, 끝 표식이 없는 누름틀은 값을 넣을 수 없어 그대로 두고 건너뜁니다. **문서의 자리**에 "채우지 못함"과 모양으로, 대조표에 "채울 수 없는 누름틀"로 미리 표시되고, 보고서의 "건너뜀"에도 나옵니다.
- **메일 머지 필드**(한컴 메일 머지용 필드. 키가 들어 있음)는 누름틀처럼 채웁니다: 필드의 키를 데이터 키로 써서 표시 글을 값으로 바꾸고 필드는 그대로 둡니다. 키에 공백·괄호가 있으면 채우지 않고 알립니다. 메일 머지를 더 쓰지 않을 서식은 명령줄 `compile --merge-fields to-placeholder`(또는 `to-field`)로 `{{키}}`나 누름틀로 한 번에 바꿀 수 있습니다.
- 한컴의 다른 필드(책갈피, 날짜, 계산식, 키 없는 메일 머지 등)는 자리가 아니라서 건드리지 않고, **문서의 자리**에도 나오지 않습니다.
- 채울 수 있는 자리가 문서에 하나도 없거나, 가진 자리가 전부 건너뛰어지거나 "원래 글 유지"여서 **채운 자리가 하나도 없으면 그 건은 실패**입니다(원본과 같은 파일을 만들지 않습니다).

## 3. 데이터(JSON) 만들기

JSON은 데이터를 적는 약속된 글 형식입니다. 메모장 같은 편집기로 만들고 **UTF-8**로 저장하세요. 엑셀·CSV 파일은 올릴 수 없습니다.

**한 건**: 중괄호 하나. 문서의 `{{project.name}}`은 아래의 "알파 사업"으로 채워집니다.

```
{ "project": { "name": "알파 사업", "start": "2026-01-01" }, "manager": "홍길동" }
```

**여러 건**: 대괄호 안에 건마다 중괄호 하나. 건이 N개면 결과 파일도 N개입니다(한 번에 1000건까지).

```
[
  { "project": { "name": "알파 사업" }, "manager": "홍길동" },
  { "project": { "name": "베타 사업" }, "manager": "김철수" }
]
```

**묶음 형식**: `schema`를 적고 `data`에 위의 한 건 또는 여러 건을 넣습니다. `derived`는 `data`에 없는(또는 null인) 키를 보충하는 값이며 모든 건이 함께 씁니다.

```
{ "schema": "hwpx-studio/dataset@1", "data": [ { "manager": "홍길동" }, { "manager": "김철수" } ], "derived": { "회사": "예시 주식회사" } }
```

값으로 쓸 수 있는 것은 글자, 숫자, true/false입니다(숫자·true/false는 글자로 바뀌어 들어갑니다). 중괄호나 대괄호로 된 값(객체·배열)은 자리에 넣을 수 없습니다. 값이 `null`이거나 키가 없으면 "데이터 없음 / null"입니다. 여러 건의 데이터 항목 하나가 객체가 아니면 그 건만 실패합니다.

### 줄바꿈이 있는 값

JSON에서는 줄바꿈을 `\n`으로 적습니다. 예: `"주소": "서울시 가구\n나동 1번지"`. **줄바꿈이 든 값은 그대로 들어갑니다.** 값의 줄바꿈은 문서 안에서 같은 문단 안의 줄바꿈이 되고(문단이 나뉘지 않습니다), 탭(`\t`)은 탭이 됩니다. 윈도에서 만든 줄바꿈(`\r\n`)도 줄바꿈 하나로 들어갑니다. 대조표에는 "데이터 있음" 뒤에 "줄바꿈/탭 유지"가 붙고, 결과의 "알림" 열에는 "값에 줄바꿈·탭이 있어 … 넣었습니다"라고 알려 주기만 하고, 오류나 건너뜀이 아닙니다.

글에 넣을 수 없는 제어 문자(보이지 않는 특수 문자)가 값에 있으면 그 건이 실패합니다. 다른 프로그램에서 복사한 글에 숨어 있는 경우가 있습니다. 대조표에는 "값 문자 차단"으로 나옵니다.

## 4. 화면에서 하는 일

빠른 생성 화면(`/quick`)은 왼쪽·가운데·오른쪽 세 칸입니다.

1. 왼쪽 **템플릿 준비**에서 **HWPX 문서 올리기**로 .hwpx를 고릅니다. 가운데 **원본 문서**에 문서가 보이고(읽기 전용), 왼쪽 **문서의 자리**에 찾은 누름틀·`{{키}}`·빈칸 후보(라벨 옆 빈 칸, `라벨:` 뒤 빈 곳, 빈칸 표시)가 나옵니다. 빈칸 후보는 **알려 주기만 하고 채우지 않습니다.** 키 이름이 규칙 밖인 자리(`{{추정가격(원)}}`처럼 괄호·공백이 든 `{{…}}`, 그런 이름의 누름틀·메일머지)는 **규칙 밖 키** 목록과 노란 안내 줄에 따로 나옵니다. 이 자리는 채우지 않고 결과에 그대로 남습니다.
2. 오른쪽 **JSON 데이터**에서 **JSON 데이터 올리기**로 .json을 고릅니다. 건수가 나오고, **데이터 경로 목록**에서 내 데이터의 키를 볼 수 있습니다.
3. 오른쪽 **자리 · 데이터 대조표**에서 자리마다 데이터와 맞는지 봅니다. 여러 건이면 "맞음 N / 누락 M"으로 건수가 함께 나옵니다.
   - **데이터 있음**: 채울 수 있습니다. "줄바꿈/탭 유지"가 붙으면 줄바꿈·탭이 든 값이며 문제가 아닙니다.
   - **데이터 없음 / null**: 데이터에 그 키가 없거나 값이 null입니다. 철자나 대소문자를 보세요.
   - **객체·배열**: 값이 중괄호·대괄호로 되어 있습니다. 안쪽 항목(`키.이름`)을 쓰세요.
   - **값 문자 차단**: 글에 넣을 수 없는 제어 문자가 있어 그 건은 실패합니다(3절).
   - **데이터 경로로 쓸 수 없는 이름**: 누름틀 이름이나 `{{…}}`의 키를 글자·숫자·`_`·`-`로 고쳐야 합니다(2-1·2-2). 대조표 위 요약에는 "규칙 밖 키 N개(채우지 않음)"로 나옵니다.
   - **채울 수 없는 필드**: 괄호 안의 사유를 보고 한컴에서 한 문단 안의 글만 담는 누름틀로 다시 만듭니다.
4. (필요할 때) `{{키}}`·누름틀이 없는 곳을 채우려면 가운데 문서에서 클릭하거나 끌어 고른 뒤, 오른쪽 **선택한 위치**에서 **연결할 데이터 경로**를 고르고 **선택한 자리 연결**을 누릅니다. 왼쪽 **명시적으로 연결한 자리**에 쌓입니다. 이 연결은 지금 작업에만 쓰이고 저장되지 않습니다.
5. 오른쪽 **생성 설정**의 **값이 없을 때**를 고릅니다.
   - **해당 건을 실패로 처리**(기본): 그 건은 만들지 않습니다. 빠뜨린 값을 놓치지 않으려면 이 방식이 안전합니다. 값이 다 있어도 **채우지 못한 `{{…}}`가 결과에 남으면**(키 이름이 규칙 밖, 글자 모양이 중간에 바뀐 `{{키}}`, 키가 규칙 밖인 메일머지의 표시 글) 그 건은 실패이고, 오류 칸에 "남은 자리 N곳: {{키}} n곳, …"이 나옵니다.
   - **원래 글 유지**: 그 자리의 글(`{{키}}` 또는 누름틀 안내문)을 남기고 나머지만 채웁니다. 채울 자리가 하나도 없으면 그 건은 실패합니다. 결과에 `{{…}}`가 남으면 성공이지만 결과 칸이 노란 "일부 채움 · … · 남은 자리 N곳"이 되고 알림 칸에 어느 키인지 나옵니다.
   - **빈 글로 채우기**: 값이 없는 자리를 비웁니다. 그래도 남는 `{{…}}`(키 이름 규칙 밖 등)는 "원래 글 유지"처럼 알림으로 보입니다.
6. **연결 확인 후 HWPX 생성**을 누르면 가운데 **생성 결과 · 알림** 표에 건마다 결과가 나옵니다. 한 건이 실패해도 나머지는 만듭니다. **내려받기**로 파일을 받고, **미리보기**로 화면에서 읽기만 할 수 있습니다.

채운 글이 문서에서 어떻게 보이는지는 한컴에서 직접 열어 확인해 주세요. 이상하게 보이면 어느 문서와 어느 데이터인지 알려 주세요.

### 메일머지 서식 채우기

한컴 메일머지 필드로 자리를 만든 서식도 같은 화면(`/quick`)에서 채웁니다. 시험용 예시: `examples/quick/template-mailmerge.hwpx`와 `data-mailmerge.json`.

1. 서식을 올리면 **문서의 자리**에 "누름틀·메일머지 키 N개 · M곳 (메일머지 a · 누름틀 b)"와 키마다 "메일머지 키 · n곳"이 나옵니다. 필드 안에 적힌 `{{키}}`는 그 필드가 채우므로 `{{키}}` 목록에 따로 세지 않습니다.
2. JSON을 올리면 대조표 위에 "데이터와 맞는 자리 N개 키 · M곳 (메일머지 …)"과 데이터 없음·이름 규칙 밖 키 수가 나옵니다. JSON의 키는 필드의 키와 같아야 합니다.
3. 생성합니다. 키에 공백·괄호가 있는 필드는 채우지 않고 건너뜁니다. **건너뜀** 칸의 `[메일머지 "키"]`가 어느 필드인지 알려 줍니다. 그 필드의 표시 글이 `{{키}}`이면 결과에 그대로 남으므로, 기본(실패로 처리)에서는 그 건이 "실패 · N곳 채움 · 남은 자리 M곳"이 되고 파일을 만들지 않습니다. **원래 글 유지**로 바꾸면 "일부 채움 · N곳 채움 · K곳 건너뜀 · 남은 자리 M곳"(노란 글)으로 만들어지고 위 상태줄에 남은 키가 적힙니다.
4. 건너뛴 필드도 채우려면 한컴에서 그 필드의 키를 글자·숫자·`_`·`-`로 고쳐 다시 올립니다. 작업창(`/`)의 추천 목록에도 메일머지 필드가 "입력 · 메일머지"로 나오고, 이름 규칙 밖 키는 노란 점선 밑줄로 보입니다.

### G2B Helper JSON으로 만들기

G2B Helper가 내보낸 JSON 파일(생성 요청과 같은 꼴: `"format": "studio-generate"`, `"version": 2`)을 그대로 올릴 수 있습니다. 시험용 예시: `examples/quick/template-mailmerge.hwpx`와 `data-helper-export.json`. 값은 전부 가짜입니다. 예전 Helper 파일(`"format": "g2b-helper-document"`, `version` 1)과 예전 생성 요청 꼴(`fields`·`userValues`)은 더 알아보지 않습니다(한 건짜리 보통 JSON으로 읽혀 대부분 "데이터 없음"이 됩니다). Helper에서 새 꼴로 다시 내보내 주세요.

1. `/quick`에서 서식(.hwpx)을 올립니다.
2. **JSON 데이터 올리기**로 Helper가 준 .json을 고릅니다. 데이터 칸에 "Helper JSON 2건(Helper 내보내기)"처럼 나오고, 대조표 위 요약도 "Helper JSON 2건 · …"으로 시작합니다. 파일의 `items`에서 **항목 하나가 한 건**(결과 파일 하나)이고, 항목의 `values`의 열 이름이 데이터 키입니다. `values`가 없는 항목은 그 건만 실패합니다. `version`이 2가 아니면 파일을 받지 않습니다.
3. 대조표에서 "데이터 없음"인 키를 봅니다. 문서의 `{{키}}`·누름틀 이름·메일머지 키가 Helper의 열 이름과 같아야 채웁니다.
4. **연결 확인 후 HWPX 생성**을 누릅니다. 결과에 `{{…}}`가 남는 건은 기본 설정에서 실패로 나오고, 남은 키가 오류 칸에 적힙니다(5절).

작업창(`/`)도 같은 판정을 씁니다. 데이터 메뉴의 **연결 안 된 입력 자리**가 "생성 막기(기본)"이면 결과에 `{{…}}`가 남거나 데이터에 없는 키가 있을 때 생성하지 않고 상태줄에 남은 곳 수와 키를 적습니다. "자리 유지"로 바꾸면 만들고 "남은 자리 N곳"을 알립니다. TXT와 HWPX 둘 다 그렇습니다.

## 5. 결과는 어디에 저장되나

- 빠른 생성 화면은 결과를 폴더에 저장하지 않고 **내려받기**로만 줍니다(작업 공간 폴더에 저장하기·폴더 열기는 아직 옮기지 않았습니다). 내려받은 파일은 브라우저의 내려받기 폴더에 생깁니다.
- 파일 이름은 `원본이름-001.hwpx`, `원본이름-002.hwpx`처럼 건 번호(1부터)가 붙습니다. 한 건이어도 `-001`이 붙습니다. 이름에 쓸 수 없는 글자는 `_`로 바뀝니다. 실패한 건은 파일이 없습니다.
- **올린 원본 문서와 데이터는 디스크에 저장하지 않고**(프로그램이 켜져 있는 동안만 메모리에 있고, 끄면 사라집니다), 원본 파일도 고치지 않습니다.

## 6. 문제가 났을 때 보고서의 어느 줄을 볼까

생성 뒤 가운데 **생성 결과 · 알림** 표에 건마다 한 줄이 나옵니다.

- **결과**: 성공/실패.
- **채운 자리**: 그 건에서 값을 넣은 곳의 수입니다. 같은 키가 여러 곳이면 곳마다 셉니다.
- **건너뜀**: 채우지 않고 넘어간 자리와 이유입니다. 건너뛰어도 그 건은 성공일 수 있으니 꼭 읽어 보세요.
- **오류**: 실패한 이유입니다(붉은 글).
- **알림**: 실패도 건너뜀도 아닌 참고 사항입니다(예: 줄바꿈이 든 값을 넣었음).

건너뜀·알림 줄은 `[어느 자리] 쉬운 설명 코드` 모양이고, 오류 줄은 `쉬운 설명 코드`이며 어느 자리인지는 설명 안에 적힙니다. 코드(`DATA_MISSING` 같은 영문)는 사람에게 문의할 때 알려 주면 빨리 찾을 수 있습니다. 자주 만나는 줄:

| 줄에 나오는 말 | 하면 되는 일 |
| --- | --- |
| 데이터에 이 키의 값이 없습니다 | 데이터에 키를 더하거나, 철자를 맞추거나, 누락 정책을 바꿉니다 |
| 글자 모양이 중간에 바뀌어 있어 건너뛰었습니다 | 한컴에서 그 `{{키}}`를 지우고 같은 글자 모양으로 한 번에 다시 입력합니다 |
| 사이에 탭·줄바꿈·그림이 끼어 있어 건너뛰었습니다 | 한컴에서 `{{키}}`를 처음부터 끝까지 이어서 다시 입력합니다 |
| 값에 글에 넣을 수 없는 제어 문자가 들어 있습니다 | 데이터에서 그 값의 보이지 않는 문자를 지웁니다 |
| 객체나 배열이어서 자리에 넣을 수 없습니다 | 안쪽 항목의 키(`키.이름`)를 문서에 적습니다 |
| 이 누름틀은 안에 그림·표가 있거나, 표 칸 경계를 넘거나, 끝 표식이 없거나, 사이 문단에 구역 설정이 있거나, 다른 누름틀과 엇갈려 값을 넣을 수 없어 그대로 두었습니다 | 한컴에서 그 누름틀을 한 문단 안의 글만 담도록 다시 만듭니다 |
| 이 누름틀은 여러 문단에 걸쳐 있어서 첫 문단에 값을 넣고 그 사이 문단을 지웠습니다 | 알림입니다. 결과를 한컴에서 열어 사라진 문단이 없는지 확인합니다 |
| 누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 누름틀 이름을 글자·숫자·`_`·`-`(안쪽 항목은 점)로 고칩니다 |
| 메일 머지 필드의 키가 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 그 필드의 키를 고치거나, `compile --merge-fields`로 바꾼 뒤 `{{키}}`를 고칩니다 |
| 채운 자리가 하나도 없어 결과를 만들지 않았습니다 | 문서의 `{{키}}`·누름틀 이름과 데이터의 키가 맞는지 비교합니다. 누름틀 이름이 키와 같아야 합니다 |
| 채우지 못한 {{…}} 자리가 결과에 남아 이 건을 만들지 않았습니다 (남은 자리 N곳: …) | 적힌 키를 서식에서 고치거나(괄호·공백 빼기, 한 글자 모양으로 다시 입력) 데이터에 더합니다. 그대로 두려면 '값이 없을 때'를 '원래 글 유지'로 바꿉니다 |
| 채우지 못한 {{…}} 자리가 결과에 그대로 남아 있습니다 | 알림입니다. 결과를 쓰기 전에 적힌 키 자리를 한컴에서 확인합니다 |
| Helper 항목의 원천 값과 사용자 입력에 같은 이름이 있어 이 건을 만들지 않았습니다 | Helper에서 사용자 입력 열 이름을 원천 열과 다르게 바꿔 다시 내보냅니다 |
| 이 파일은 .hwpx 문서가 아닙니다 / 옛 형식(.hwp)입니다 | 한컴에서 .hwpx로 다른 이름으로 저장해 다시 올립니다 |
| …새 오류가 생겨, 안전을 위해 결과를 만들지 않았습니다 | 프로그램이 안전 검사에서 멈춘 것입니다. 문서와 데이터를 알려 주세요 |

## 7. 지금의 한계

- **빠른 생성에서는 키에 공백·점이 들어 있으면 쓸 수 없습니다.** 엑셀 머리글처럼 "회사 이름", "금액(원)", "a.b"가 키인 데이터는 키 이름을 글자·숫자·`_`·`-`로 바꿔야 합니다(점은 안쪽 항목으로만 쓰입니다). 2판 템플릿(8절)은 연결에 머리글을 그대로 적을 수 있습니다.
- **그림·도형 자리**: 그림 자체를 바꾸거나 그림·도형을 채우는 기능은 없습니다. 글상자·표·머리말·꼬리말·각주 안의 글은 채워집니다.
- **후보 자리**(빈칸 표시 등)는 알려 주기만 하고 채우지 않습니다.
- 여러 문단에 걸친 누름틀을 채우면 사이 문단이 지워집니다(한컴과 같은 동작). 지워지면 안 되는 내용이 사이에 있으면 누름틀을 한 문단 안으로 다시 만드세요.
- 메일 머지 필드도 누름틀처럼 채웁니다(2-2). 키에 공백·괄호가 있는 필드는 빠른 생성에서는 채우지 않고 알립니다.
- "원래 글 유지"로 남겨 둔 자리 가운데 `{{…}}`는 "남은 자리"로 알리지만, 누름틀 안내문으로 남은 자리는 보고서에 따로 적히지 않습니다. 대조표의 "데이터 없음 / null"로 어느 키가 없었는지 확인하세요.
- 데이터 값 안에 `{{…}}` 글이 있으면 그 글은 값 그대로 들어가고 남은 자리로 세지 않습니다.
- Helper JSON의 열 이름은 바꾸지 않고 그대로 키로 씁니다. 열 이름에 공백·괄호가 있으면 빠른 생성의 키 규칙 밖이라 채울 수 없습니다(문서 쪽 이름도 같아야 하고 규칙 안이어야 합니다).
- 빠른 생성은 값을 데이터에 보이는 그대로 넣습니다. 값을 꾸미려면 2판 템플릿의 값 형식(8절)을 씁니다: 금액(`money`)은 `1234000`·`1,234,000`·`금 1,234,000원정`을 단위 없이 `1,234,000`으로 넣고("원"을 붙이려면 값의 표시 설정 `"display": { "unit": "원" }`. 그래도 문서에서 자리 바로 뒤에 이미 "원"이 있으면 숫자만), 날짜(`date`)는 `20261009`·`2026-10-09`·`2026. 10. 9.`를 `2026. 10. 09.`로 넣습니다. 수·백분율·일시·참거짓 형식도 있고, 표시 꼴은 템플릿에서 바꿀 수 있습니다([엔진 명세](engine-spec.md) 8.8.4).
- 여러 문단을 한 덩어리로 바꿔 넣는 범위 지정은 명령줄(8절)과 뷰어의 끌기 초안으로 할 수 있습니다. 화면에서 지정해 저장하는 것은 다음 단계입니다.
- 한 번에 1000건까지입니다. 화면이 한 번에 보내는 양이 32MB까지라서 .hwpx는 약 24MB, .json은 약 32MB까지 올릴 수 있습니다. 건이 많거나 문서가 크면 만드는 동안 화면이 잠시 멈춥니다.
- 만든 결과 파일에는 원본의 미리보기 글·그림과 작성자 정보가 그대로 남아 있을 수 있습니다. 밖으로 보내기 전에 한컴에서 확인하세요(정리 기능은 아직 없습니다. #15).
- 화면에서 클릭으로 연결한 자리는 지금 작업에만 쓰이고 저장되지 않습니다. 문서 내용을 고치려면 한컴에서 고친 뒤 다시 올립니다.

## 8. 조항을 바꿔 넣는 템플릿(2판) — 명령줄로 먼저

공고서의 한 조항(예: 참가 자격)을 금액이나 이번 건의 선택에 따라 다른 글로 통째로 바꿔 넣는 방법입니다. 화면은 다음 단계(Codex)이고, 지금은 명령줄로 합니다. 예시 파일과 고쳐 볼 거리는 [`examples/template-v2/README.md`](../examples/template-v2/README.md)에 있습니다.

말뜻:

- **값**: 이름과 형식을 가진 데이터 한 칸입니다. 형식이 금액(`money`)이면 `150000000`이 `150,000,000`으로 들어갑니다("원"은 표시 설정 `"display": { "unit": "원" }`으로 붙입니다).
- **자리**: 문서의 `{{키}}`처럼 값이 들어갈 곳입니다. 어느 값을 받는지 템플릿에 적어 둡니다.
- **슬롯**: 문서에서 내용을 통째로 바꾸는 곳입니다. 번호 제목 하나부터 다음 같은 단계 제목 앞까지(제목 범위), 또는 정한 문단들(범위)로 잡습니다.
- **블록**: 슬롯에 들어갈 내용 한 가지입니다. 글이거나, 다른 문서에서 떠 온 조각(표 포함)입니다. 블록마다 고르는 조건을 둘 수 있습니다.
- **이번 건**: 이 건에서만 쓰는 선택과 고친 값입니다(`case.json`). 템플릿과 데이터는 바꾸지 않습니다.

순서(저장소 폴더에서):

1. 제목 보기: `node apps/cli/src/main.ts headings examples/template-v2/notice.hwpx`. 프로그램이 알아본 번호 제목과 단계가 나옵니다. 슬롯은 이 제목으로 잡습니다.
2. 만들기: 아래를 입력하면 `result.hwpx`와 보고서 `report.json`이 생깁니다. 다시 만들 때는 끝에 `--overwrite`를 붙입니다.

```
node apps/cli/src/main.ts fill examples/template-v2/notice.hwpx --template examples/template-v2/template.json --case examples/template-v2/case.json --blobs examples/template-v2/blobs --data examples/template-v2/data.json -o result.hwpx --report report.json
```

3. 화면에 `슬롯 s1: b1 (default)`, `슬롯 s2: b4 (manual)`처럼 슬롯마다 고른 블록이 나옵니다. `result.hwpx`를 한컴에서 열어 봅니다.

블록을 고르는 법:

- **금액 조건**: 예시의 참가 자격 슬롯은 추정가격이 1억 원 이상이면 b1, 10억 원 이상이면 표가 든 b3(우선순위가 높음), 둘 다 아니면 조건 없는 b2를 넣습니다. `data.json`의 금액만 바꿔도 들어가는 조항이 바뀝니다. 금액은 쉼표 없는 숫자로 적습니다.
- **수동 선택**: 조건 없는 블록이 둘 이상인 슬롯(예시의 제출 서류)은 `case.json`의 `selections`에서 직접 고릅니다. 고르지 않으면 `SEL_UNDECIDED`로 멈추고 결과를 만들지 않습니다. 고른 블록은 데이터가 바뀌어도 그대로입니다.

결과 보고서(`report.json`)에서 볼 곳:

- `report.selections`: 슬롯마다 고른 블록과 이유(`default` 조건이 참, `fallback` 조건 없는 블록, `manual` 직접 고름, `undecided`·`recheck` 막힘).
- `report.moves`: 블록을 넣으면서 문단 번호가 얼마나 움직였는지입니다.
- `report.dropped`: 블록이 덮어서 빠진 자리입니다(실패 아님).
- `report.issues`: 오류의 코드와 설명입니다. 자주 만나는 코드와 할 일은 예시 README의 표에 있습니다.

원본 `notice.hwpx`를 한컴에서 고쳐 저장하면 템플릿이 기억하는 원본과 달라져 `TPL_SOURCE_MISMATCH`로 막힙니다. 예시에서는 `node tools/examples/make-template-v2.ts --refresh`로 템플릿을 새 원본에 맞춥니다.

## 9. 표 보기로 한꺼번에 이름 붙이기 (작업창 `/`)

값이 이미 적힌 공고서에서 "바뀌는 곳"을 먼저 죽 짚어 두고, 이름과 데이터 키는 표에서 한꺼번에 적는 방법입니다. 원문 글은 바뀌지 않고, 확정한 곳만 생성 결과에서 데이터 값으로 바뀝니다.

연습용 문서(값은 전부 가짜)는 예시 서식에 예시 데이터를 채워 만듭니다. 저장소 폴더에서:

```
node apps/cli/src/main.ts fill examples/quick/template-braces.hwpx --data examples/quick/data-single.json -o 표보기-연습.hwpx
```

1. `npm run start:lite`로 켜고 `http://127.0.0.1:4318/`을 엽니다. **열기 → 문서 열기**로 `표보기-연습.hwpx`를 엽니다.
2. 왼쪽 **데이터**를 펼쳐 **파일 열기**로 `examples/quick/data-single.json`을 올립니다(데이터가 없어도 됩니다. 그러면 키 칸이 자동으로 채워지지 않고, 견본 값 칸에 값을 직접 적어 미리 볼 수 있습니다. 12절).
3. 원문에서 바뀌는 값(예: `홍길동`, `예시 주식회사`, `010-0000-0000`)을 하나씩 누르거나 끌어 고르고, 옆에 뜬 리모컨에서 **지정**을 누릅니다. 이름은 적지 않아도 됩니다(이름 칸을 비운 채 Enter를 눌러도 지정됩니다). 왼쪽 추천 목록에 "지정" 줄이 생기고 원문 위에 "이름 없음 · 지정" 꼬리표가 붙습니다.
4. 추천 목록 위의 **크게 보기**를 누릅니다. 왼쪽이 넓어지며 표가 나옵니다. 한 줄이 한 곳이고 칸은 원문 글 · 이름 · 데이터 키 · 견본 값 · 타입 · 상태입니다.
5. 첫 줄의 **이름** 칸에 커서가 있습니다. `성명`을 치고 Enter, `소속`을 치고 Enter …처럼 아래로 내려가며 적습니다(↓·↑로도 움직입니다). 줄을 옮길 때마다 가운데 원문이 그 자리로 이동해 강조됩니다.
6. 이름이 데이터의 키와 같으면 **데이터 키** 칸이 기울어진 글씨로 저절로 채워지고 **견본 값**에 그 데이터 값이 보입니다. 이름과 키가 다르면(예: 이름 `전화번호`, 키 `연락처`) Tab으로 데이터 키 칸에 가서 직접 적습니다.
7. 줄 끝의 **✓**로 한 줄씩, 또는 표 위 **✓ 전체 확정**으로 이름이 있는 줄을 한꺼번에 확정합니다. 상태가 "확정"으로 바뀌고 추천 목록·꼬리표도 같이 바뀝니다. 이름이 없거나 확정할 수 없는 줄은 남고 상태줄에 이유가 나옵니다.
8. **생성**을 누르면 확정한 곳에 데이터 값이 들어간 결과가 "생성 미리 보기"에 나옵니다. **원문** 탭은 그대로입니다.
9. **저장**(Ctrl+S)으로 작업 파일을 받아 두면, 나중에 **열기 → 작업 불러오기**로 이름·키·타입·상태가 그대로 돌아옵니다. **작게 보기**로 표를 닫습니다.

알아 둘 것:

- 확정을 잘못했으면 Ctrl+Z로 되돌립니다(확정 → 지정 → 지정 전 순서). 확정한 줄의 데이터 키를 바꾸려면 먼저 되돌립니다. 이름은 확정 뒤에도 바꿀 수 있고 키·위치는 그대로입니다.
- 한 문단 안에서 글자 모양(색·굵기 등)이 다른 글을 함께 고르면 "글자 모양이 다른 글에 걸쳐 있어…"가 나오고 지정되지 않습니다. 라벨과 값이 한 문단인 표 칸에서는 **값 부분만** 끌어 고릅니다.
- 문서에 원래 있던 누름틀·메일머지·`{{키}}`도 "추천" 줄로 표에 나옵니다. 누름틀·메일머지의 키 칸은 처음에 필드 이름이고, 이름이 다른 데이터 열에 이으려면 키 칸을 바꿉니다(12절).
- 타입(금액·날짜·시각·전화·수량·글·긴 글)과 라벨은 아래 10절을 보세요.
- 체크를 끄면 그 줄은 "제외"입니다. 원문은 지워지지 않고, 다시 체크하면 돌아옵니다.

## 10. 타입 고르기와 참고 글 지정 (작업창 `/`)

지정한 곳마다 표 보기가 **라벨**(그 값이 무엇인지 알려 주는 가까운 글)과 **타입**(금액·날짜 같은 값의 모양)을 저절로 채웁니다. 라벨에서 이름을 추천하고, 타입은 생성 결과의 꾸밈(금액 쉼표, 원문 날짜 모양)에 씁니다. 원문 글은 바뀌지 않습니다.

연습용 문서(값은 전부 가짜)는 예시 서식에 `data-types.json`의 첫 건을 채워 만듭니다. 저장소 폴더에서:

```
mkdir 타입연습
node apps/cli/src/main.ts fill examples/quick/template-braces.hwpx --data examples/quick/data-types.json --batch -o 타입연습
```

`타입연습/template-braces-001.hwpx`(첫 건: 금액 `1,234,000원`, 날짜 `2026. 10. 7.`, 전화 `02-123-4567`)를 연습 문서로 씁니다.

1. 작업창에서 `타입연습/template-braces-001.hwpx`를 열고, 왼쪽 **데이터**에서 `examples/quick/data-types.json`을 올립니다. 상단 **생성** 옆 **업무 건**에서 **2건**을 고릅니다(둘째 건이 생성에 쓰입니다: 금액 `2500000`, 날짜 `2026-11-02`, 전화 `031-987-6543`).
2. 원문에서 `홍길동`, `02-123-4567`, `예시 사유입니다.`, `1,234,000원`, `2026. 10. 7.`을 하나씩 골라 리모컨의 **지정**을 누릅니다. 상태줄에 "신청인 입력 항목을 지정했습니다"처럼 **라벨에서 온 이름**이 나옵니다.
3. **크게 보기**를 누릅니다. **원문 글** 칸 앞에 `신청인 · 앞 글`, `비고 · 행 머리` 같은 라벨 표지가 있고, 그 뒤에 지정할 때 담아 둔 앞뒤 글이 회색으로 보입니다(마우스를 올리면 전체). 관계는 **앞 글**(같은 문단의 `라벨:`), **행 머리**(같은 표 행 왼쪽 칸), **제목**(위 제목), **참고 글**(손으로 고른 글)입니다.
4. **이름** 칸의 기울어진 글씨는 라벨에서 추천한 이름입니다. 맞으면 그대로 두고, 아니면 고쳐 적습니다(예: `신청인` → `성명`). 이름이 데이터 키와 같으면 키 칸이 저절로 채워집니다. **데이터 키** 칸에 들어가면 키 목록이 이름·라벨과 비슷하고 타입이 맞는 것부터 보입니다(예: `신청 사유` 줄은 `신청사유`가 맨 위).
5. **타입** 칸은 원문 모양으로 추천한 것이 기울어진 글씨로 들어 있습니다(`1,234,000원` → 금액, `2026. 10. 7.` → 날짜, `02-123-4567` → 전화, `5개` → 수량 · 개). 바꾸려면 칸을 눌러 7종 가운데 고릅니다. 고른 타입은 보통 글씨가 되고, 이름을 고쳐도 다시 추천으로 바뀌지 않습니다.
6. **라벨이 없는 곳**(예: `예시 주식회사`. `라벨:`은 쌍점 바로 뒤 첫 값에만 붙으므로 `신청인:` 뒤 둘째 값에는 라벨이 없습니다)은 그 줄을 고른 채(표에서 그 줄을 누르거나 방금 지정한 채로) 원문에서 라벨로 쓸 다른 글을 고르고, 리모컨이나 오른쪽 클릭 메뉴의 **참고 글 지정 · (항목 이름)**을 누릅니다. 그 글이 라벨(관계 **참고 글**)이 되고 이름이 비어 있었으면 그 글로 이름을 추천합니다.
7. **✓ 전체 확정** → **생성**. 생성 미리 보기에서 금액은 `2,500,000원`(쉼표, 서식에 "원"이 있으면 "원"은 한 번만), 날짜는 원문과 같은 모양 `2026. 11. 2.`(원문 `2026. 10. 7.`처럼 월·일이 한 자리), 전화는 받은 그대로 `031-987-6543`입니다. 이 문서로 Helper 프로필(11절)을 만들어 같은 건을 받아도 같은 글입니다.
8. **저장**한 작업 파일을 다시 열면 라벨·관계·앞뒤 글·타입(고른 것인지 추천인지 포함)이 그대로입니다.

알아 둘 것:

- 금액·날짜 꾸밈은 지정·확정한 곳과 문서에 원래 있던 누름틀·메일머지·`{{키}}` 모두에 쓰고(블록을 배치한 생성 포함), Helper 프로필로 만든 파일과 같은 글입니다. 수량 꾸밈(원문 단위)은 작업창에서 확정한 곳에만 씁니다.
- 같은 금액이 여러 곳에 들어가도 "원"은 곳마다 정합니다: 바로 뒤에 "원"이 있는 곳은 숫자만, 없는 곳은 지정한 원문이 "원"으로 끝났으면 "원"을 붙입니다.
- 지정한 날짜는 원문 모양을 따릅니다. 월·일 가운데 한 자리가 있으면(`2026. 10. 7.`) `2026. 11. 2.`, 두 자리면(`2025. 12. 31.`·`2026-10-07`) `2026. 11. 02.`·`2026-11-02`, `2026년 10월 7일`이면 `2026년 11월 2일`입니다. 같은 키의 지정 날짜 모양이 여럿이면 첫 곳의 모양을 쓰고, 요일 괄호(`(수)`)는 넣지 않습니다.
- 원문에 날짜 모양이 없는 자리(예: `{{계약일}}`)에 날짜 타입을 주면 `2026. 11. 02.`(YYYY. MM. DD.)로 넣습니다. `미정`처럼 날짜·수가 아닌 값은 그대로 넣습니다.
- 금액 원문 앞의 `금 `까지 지정하면 `금 `은 값에 남지 않습니다. `금 `은 빼고 숫자부터 고르세요.
- 금액·날짜 타입이 있는 생성에서 `{{키}}` 글자 가운데 일부만 굵게 하는 식으로 서식이 섞인 자리가 있으면 "자리 유지"를 골라도 생성이 막힙니다(Helper 생성도 같습니다). 한컴에서 키 전체를 같은 서식으로 고치세요.
- 전화·식별번호는 글 그대로 넣으므로 앞자리 0이 남습니다. 데이터에서 따옴표 없는 수(`0212345678`이 아닌 `212345678`)로 적으면 0은 이미 없습니다.
- 라벨·이름에는 괄호·공백이 들어가도 됩니다. 데이터 키는 공백 없이 적습니다(공백 든 이름이면 키 칸에 따로 적습니다).
- 제목은 라벨로만 저장하고 이름으로는 추천하지 않습니다(같은 제목 아래 여러 값이 같은 이름이 되지 않게).

## 11. Helper 프로필 저장 (작업창 `/`)

G2B Helper가 Studio에 생성을 맡길 때 쓰는 **프로필**(어느 서식 판으로, 어느 폴더에 만들지)을 작업창에서 저장합니다. 연습 문서는 `examples/quick/template-mailmerge.hwpx`입니다(값은 전부 가짜).

1. 작업창에서 문서를 열고 왼쪽 **흐름** 탭의 **Helper 프로필**을 엽니다.
2. **서식 판 저장**을 누릅니다. 문서에 있는 누름틀·메일머지·`{{키}}`(추천 목록에서 제외한 것은 빼고)가 서식의 자리가 되고, 옆에 `1판 · template-mailmerge`처럼 판 번호가 나옵니다. 표 보기의 타입이 금액·날짜인 자리는 그 형식으로, 나머지는 글로 저장합니다.
3. **프로필 이름**과 **출력 폴더**(드라이브부터 적은 경로. 예: `D:\공고\출력`)를 적고 **프로필 저장**을 누릅니다. 아래 목록에 이름, 서식 id와 판, 폴더, 프로필 id가 나옵니다. Helper는 이 목록을 읽어 프로필을 고릅니다.
4. 서식이 바뀐 뒤(추천 목록에서 줄을 빼거나 타입을 바꾼 뒤, 한컴에서 고친 문서를 다시 연 뒤) 프로필의 **다시 확인**을 누르면 지금 문서로 새 판을 저장하고 프로필을 그 판으로 바꿉니다("1판에서 2판으로 바꿨습니다"). 바뀐 것이 없으면 "서식이 그대로입니다"가 나옵니다. 누르기 전까지 프로필은 저장할 때의 판을 그대로 씁니다.
5. **삭제**는 프로필만 지웁니다. 저장한 서식 판과 이미 만든 결과 파일은 그대로입니다.

알아 둘 것:

- 같은 문서·같은 자리로 다시 저장하면 판 번호가 늘지 않습니다.
- 표 보기에서 지정·확정하고 이름을 적은 자리도 서식 판에 들어가고, 데이터 연결(12절)은 Helper가 보내는 열 이름에도 그대로 쓰입니다. 이름이 데이터 키와 다르면 이름 그대로 오는 열도 받습니다.
- 같은 메일머지 키가 여러 곳에 있으면 그 키의 모든 곳을 함께 채웁니다. 자리에서 빼려면 그 키의 줄을 모두 제외합니다.

## 12. 데이터 연결과 업무 건 (작업창 `/`)

입력 항목마다 **어느 데이터 열을 넣을지**(데이터 연결)를 정하고, 데이터 한 건(**업무 건**)을 골라 바로 만들거나 미리 봅니다. 연습 파일은 `examples/quick/template-braces.hwpx`와 `examples/quick/data-multi.json`(세 건, 값은 전부 가짜)입니다. 원문 글은 바뀌지 않습니다.

1. 작업창에서 `template-braces.hwpx`를 열고 왼쪽 **데이터**에서 `data-multi.json`을 올립니다. 상태줄에 "3개 업무 건을 올렸습니다"가 나오고, 상단 **생성** 옆 **업무 건**에 `1건 · 홍길동`, `2건 · 김영희`, `3건 · 이철수`가 생깁니다.
2. 원문에서 `위와 같이`를 골라 리모컨의 **데이터 연결**을 누릅니다. 그 자리가 지정되고 리모컨 아래에 **데이터 키** 목록이 열립니다. `비고`를 고르면 "…비고에 연결했습니다"가 나옵니다. 이름을 바꿔도 연결한 키와 자리는 그대로입니다.
3. 문서에 있던 `{{성명}}`처럼 이름이 데이터 키와 같은 자리는 키가 저절로 채워집니다(연결 후보). 다른 이름의 열에 이으려면 2처럼 목록에서 고르거나 표 보기의 데이터 키 칸에 적습니다. **이름이 같은 입력 항목은 함께** 같은 키에 이어집니다(같은 이름은 같은 값).
4. **크게 보기**로 표를 열면 같은 값을 받는 줄에 "같은 값 3곳"처럼 보입니다. 이름을 적고 **✓ 전체 확정**을 누릅니다.
5. **업무 건**에서 `2건 · 김영희`를 고르고 **생성**을 누르면 생성 미리 보기에 그 건의 값이 들어갑니다. 미리 보는 중에 `3건 · 이철수`로 바꾸면 상태줄에 "갱신 중 · 업무 건 3건 · 이철수"가 잠깐 나오고 미리 보기가 새 건으로 바뀝니다. 바꾸는 동안 이전 건의 결과는 내려받을 수 없습니다.
6. 바로 파일만 필요하면 업무 건을 고르고 **생성** → **HWPX 저장**을 누릅니다(미리 보기를 보지 않아도 됩니다).
7. **Helper 프로필 → 서식 판 저장**을 누르면 지정한 자리와 데이터 연결이 함께 서식 판에 들어갑니다(11절).

알아 둘 것:

- 데이터를 올렸을 때 서식에는 있는데 데이터에 없는 키가 있으면 데이터 메뉴에 "템플릿에만 있는 키 n개"가 나옵니다. 데이터에만 있는 키는 그 아래 "데이터에만 있는 키"를 펼쳐야 보입니다.
- 데이터가 없으면 표 보기의 **견본 값** 칸에 값을 직접 적어 생성 미리 보기를 만들 수 있습니다. 같은 값을 받는 줄은 한 번만 적으면 함께 바뀌고, 작업 파일에 함께 저장됩니다.
- 누름틀·메일머지를 이름이 다른 데이터 열에 이었는데 데이터에 필드 이름과 같은 열도 값이 있으면 어느 쪽을 쓸지 몰라 생성을 막습니다. 한 열만 남기세요.
- 원래 `{{키}}`가 있는 줄 안의 다른 글을 지정·확정하면 생성이 막힙니다(지금의 한계). 그런 줄은 한컴에서 `{{키}}`로 적어 두세요.
- 업무 건 이름은 건마다 값이 다른 첫 열의 값입니다. 이름 열을 고르는 기능은 아직 없습니다.

## 13. 깃발로 긴 범위 고르기 (작업창 `/`)

여러 쪽에 걸친 조항처럼 끌기 어려운 범위는 **시작 깃발**과 **끝 깃발**로 고릅니다. 결과는 같은 범위를 끈 것과 같습니다. 연습 파일은 `examples/quick/template-mailmerge.hwpx`입니다. 원문 글은 바뀌지 않습니다.

1. 원문에서 범위의 첫 문단(예: `사업명: 예전 값`)을 누르고 리모컨(또는 우클릭 메뉴)의 **시작 깃발**을 누릅니다. 그 자리에 "시작 깃발" 표식이 붙고 상태줄에 "끝 깃발을 찍으세요 · Esc로 취소"가 나옵니다.
2. 스크롤해서 마지막 문단(예: `재공고`)을 누르고 **끝 깃발**을 누릅니다. 처음부터 끝까지 강조되고 오른쪽 상세에 "문단 8개"가 보입니다. 끝을 먼저 찍고 시작을 나중에 찍어도 같습니다.
3. 리모컨의 **블록으로 저장**을 누르면 같은 범위를 끌어 저장한 것과 같은 블록이 저장됩니다.

알아 둘 것:

- 두 깃발이 같은 문단이면 "문단 1개(문단 전체)"로 그 문단 전체를 고릅니다.
- 본문과 표 칸, 또는 서로 다른 표 칸에 걸치면 "두 깃발이 서로 다른 표 칸이나 본문에 있어…"라며 받지 않습니다. 시작 깃발은 남아 있으니 같은 본문이나 같은 칸 안에서 끝을 다시 찍으세요.
- 시작 깃발을 찍은 뒤 Esc를 누르거나 다른 문서를 열거나 생성 미리 보기로 가면 깃발이 사라집니다.
- 머리말·꼬리말·쪽 번호처럼 위치를 확인할 수 없는 글은 눌러도 고를 수 없어 깃발도 찍을 수 없습니다.
- 문서 첫 문단처럼 쪽 설정이 든 문단은 블록으로 저장할 수 없습니다(끌어 고른 때와 같습니다).

## 14. 분기점 만들기와 경우 표 (작업창 `/`)

업무 건에 따라 조항이 바뀌는 곳(**분기점**)을 만들고, 저장소의 블록 가운데 어느 것을 넣을지 **경우 표**로 정합니다. 연습 파일은 `examples/template-v2/notice.hwpx`이고 값은 전부 가짜입니다. 원문 글은 바뀌지 않습니다.

1. 블록 저장소에 바꿔 넣을 블록을 2개 이상 저장해 둡니다(원문 범위를 고르고 **블록으로 저장**).
2. `notice.hwpx`를 열고 왼쪽 **데이터 → 직접 입력**에 `[{"구분":"물품","지역":"서울"},{"구분":"용역","지역":"부산"},{"구분":"물품","지역":"부산"}]`처럼 업무 건을 넣고 **데이터 사용**을 누릅니다.
3. 원문에서 `가. 입찰 공고일…`부터 `나. 최근 3년…`까지 끌어 고르고(또는 깃발) 리모컨의 **분기점 만들기**를 누릅니다. 리모컨 이름 칸에 `참가 자격`을 먼저 적으면 그 이름이 됩니다. 왼쪽 흐름 트리의 제목 아래에 "분기 참가 자격"이 생기고 오른쪽에 **분기 표**가 열립니다.
4. **후보 블록**에서 넣을 블록을 체크합니다(2개 이상). **보기**를 누르면 아래에 그 블록만 따로 그린 미리 보기가 나옵니다.
5. **경우 표**의 **결정 값**에서 `구분`을 고르고 **경우 더하기**로 `물품 → 블록 A`, `용역 → 블록 B`처럼 적습니다. **기본 블록**은 어느 경우에도 맞지 않을 때 넣는 블록입니다. 값 두 개가 모두 맞아야 하는 경우는 아래 **결정 값 더하기**에서 `지역`을 더한 뒤 줄마다 `물품`·`서울`처럼 적습니다. 줄 앞 **이름** 칸에 `물품 서울`처럼 이름을 적어 두면 흐름도에 그 이름이 보입니다.
6. **생성**을 누르고 상단 **업무 건**을 바꾸면 미리 보기에서 그 자리의 블록만 바뀝니다. 흐름 트리에는 지금 업무 건의 블록 이름이 보입니다.
7. 맞는 경우도 기본 블록도 없으면 생성을 막고 "참가 자격(맞는 경우가 없고 기본 블록도 없음)"처럼 알리며 그 분기 표를 엽니다. 분기 표 아래 **업무 건** 칸에서 블록을 직접 고르면 그 업무 건에만 적용되고 바로 미리 보기를 다시 만듭니다.
8. **Helper 프로필 → 서식 판 저장**을 누르면 분기점과 경우 표가 서식 판에 들어갑니다. Helper가 못 정한 분기는 분기점 이름과 블록 id로 되돌아오고, `selections`로 고르면 작업창과 같은 결과가 나옵니다.
9. 함께 들어가면 안 되는 두 분기점은 한쪽 분기 표의 **함께 고를 수 없는 분기점**에서 다른 분기점을 체크합니다. 어떤 업무 건에서 둘 다 경우 표 블록이 되면 생성을 막고 "함께 고를 수 없는 …도 경우 표 블록을 고름"이라고 알립니다. 그 업무 건에서 한쪽을 **기본 블록**으로 직접 고르면 풀립니다.
10. 왼쪽 **제목 흐름**의 **크게 보기**를 누르면 제목 순서대로 분기점과 후보 블록 갈래가 보이고, 지금 업무 건이 쓰는 블록이 굵게(▶) 보입니다. 갈래를 누르면 오른쪽 분기 표가 열리고, **작게 보기**로 닫으면 원래 화면으로 돌아옵니다.
11. 블록을 빼면 `[붙임 3]`이 `[붙임 2]`가 되어야 할 때는 크게 보기 위쪽 **참조 번호 다시 매기기**에서 `붙임`(필요하면 `별지`·`표`)을 체크하고 생성합니다. 문단 첫머리의 `[붙임 N]`·`<붙임 N>`·`붙임 N.`과 본문의 `붙임 N`이 실제 순서대로 바뀌고, 완료 알림에 바꾼 곳 수가 나옵니다.

알아 둘 것:

- 경우 표는 결정 값이 같은지만 봅니다(여럿이면 모두 같아야). 금액 범위(이상·이하)는 아직 없습니다.
- 업무 건마다 직접 고른 블록은 그 업무 건의 값에 붙습니다. 데이터를 다시 올려 순서가 바뀌어도 같은 건에 남고, 그 건의 값이 바뀌면 다시 골라야 합니다.
- 후보 블록 **보기**의 "입력 n · 문서와 같은 값 m"은 블록 안 입력 항목 가운데 문서에 같은 이름(데이터 키)이 있는 수입니다. 같은 이름은 같은 값으로 채워집니다.
- 결정 값을 "없음 · 직접 고름"으로 두면 후보가 둘 이상일 때 업무 건마다 직접 고릅니다. 후보가 하나뿐이면 그 블록이 들어갑니다.
- 분기점 범위와 겹치는 편집·블록 넣기는 할 수 없습니다. 분기점을 지우면(분기 표 아래 **분기점 지우기**) 그 범위는 원문 그대로입니다.
- 후보로 고른 블록은 이 작업이 쓰는 블록이라 저장소에서 지울 수 없습니다.

## 15. 제목을 하나 찍어 같은 것 전부 찾기 (작업창 `/`)

왼쪽 **제목 흐름**에 제목이 빠졌거나 제목이 아닌 것이 섞였을 때, 제목 하나를 골라 번호 모양·서식이 같은 문단을 한꺼번에 고칩니다. 연습 파일은 `examples/quick/template-mailmerge.hwpx`(찾은 제목이 없는 문서)입니다. 원문 글은 바뀌지 않습니다.

1. 원문에서 제목으로 쓸 문단(예: 첫 줄 `합성 공고서 서식`)을 우클릭하거나 눌러 리모컨을 띄우고 **이것과 같은 것 전부**를 누릅니다.
2. **추천 목록** 맨 위에 "같은 유형 n개" 묶음이 생기고 줄마다 체크되어 있습니다. 줄을 누르면 원문이 그 문단으로 갑니다.
3. 제목이 아닌 줄은 체크를 풉니다.
4. 묶음 아래 **✓ 제목으로**를 누르면 체크한 줄은 제목 흐름에 들어가고 뺀 줄은 빠지며, 제목별 **블록** 후보가 새 제목에 맞춰 바뀝니다.
5. 잘못 눌렀으면 Ctrl+Z 한 번으로 이전 제목 흐름으로 돌아갑니다. **저장**하면 고친 제목 흐름도 작업 파일에 남습니다.

알아 둘 것:

- "같은 것"은 번호 모양(`1.`·`가.`·`(1)`·`①`·`□` 등과 그 단계)·굵기·글자 크기가 모두 같은 문단입니다. 번호가 없는 보통 문장을 고르면 같은 모양의 본문이 모두 나오니 제목 문단을 고르세요.
- 이미 제목인 문단을 골라 묶음에서 일부 체크를 풀면 그 문단들은 제목에서 빠집니다.
