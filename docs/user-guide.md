# 사용 안내 — 빠른 생성

- 작성일: 2026-10-03
- 이 문서가 소유하는 주제: 비전문가가 빠른 생성 화면을 쓰는 방법(한컴에서 자리 적기, 데이터 만들기, 결과 읽기)
- 소유하지 않는 주제: 화면·API의 계약은 [스튜디오 명세](studio-spec.md) 4a절, 엔진의 규칙은 [엔진 명세](engine-spec.md)

한컴에서 `{{키}}`나 누름틀을 적어 둔 문서(.hwpx)와 데이터(.json)를 올리면, 데이터의 값으로 자리를 채운 문서를 건마다 하나씩 만들어 줍니다. 원본 문서는 고치지 않습니다.

처음이면 `examples/quick/` 폴더의 예시 서식·데이터로 먼저 해 보세요. 고쳐 가며 시험하는 순서는 그 폴더의 [README](../examples/quick/README.md)에 있습니다.

## 1. 켜는 방법

터미널에서 저장소 폴더로 가서 아래를 입력하고, 브라우저에서 `http://127.0.0.1:4174`를 엽니다. 이 주소는 내 컴퓨터 안에서만 열립니다.

```
node apps/studio/server.ts
```

결과를 저장할 폴더를 바꾸려면 `--workspace 폴더이름`을 덧붙입니다(5절). 끄려면 터미널에서 Ctrl+C를 누릅니다.

## 2. 한컴에서 자리 만들기

자리는 두 가지로 만들 수 있고, 한 문서에 섞어 써도 됩니다.

### 2-1. `{{키}}` 적기

채울 곳에 `{{` 와 `}}` 사이에 키 이름을 적습니다. 예: `사업명: {{project.name}}`

- **`{{키}}` 전체를 같은 글자 모양으로, 한 번에 이어서 입력하세요.** 입력하는 도중에 글꼴·크기·굵기·색을 바꾸면 프로그램이 `{{키}}`를 한 덩어리로 보지 못해 그 자리를 건너뜁니다(보고서에 "글자 모양이 중간에 바뀌어 있어 건너뛰었습니다"라고 나옵니다). 이미 그렇게 된 자리는 지우고 다시 입력하면 됩니다.
- `{{`와 `}}` 사이에 탭·줄바꿈·그림을 넣으면 자리로 알아보지 못할 수 있습니다. 1단계 화면의 "{{키}}" 목록에 내가 적은 자리가 모두 나오는지 꼭 확인하세요. 목록에 없으면 인식하지 못한 것입니다.
- 키 이름에는 글자(한글 포함)·숫자·`_`·`-`만 쓸 수 있습니다. 공백은 쓸 수 없습니다. 점(`.`)은 "안쪽 항목"을 뜻합니다: `{{project.name}}`은 데이터의 `project` 안의 `name` 값을 가져옵니다.
- `{{ project.name }}`처럼 괄호 안쪽에 공백을 넣어도 됩니다.
- 표 안, 글상자 안, 머리말·꼬리말·각주 안에 적은 `{{키}}`도 채워집니다.

### 2-2. 누름틀 넣기

누름틀은 한컴이 "여기에 입력하세요" 하고 안내문을 보여 주는 입력 칸입니다. 이 프로그램은 **누름틀의 이름을 데이터의 키로 씁니다.**

- 한컴에서 메뉴 **입력 → 필드 입력**(단축키 Ctrl+K, E)을 열고 **누름틀** 탭에서 안내문과 이름을 적어 넣는 방식입니다. 한컴 버전에 따라 메뉴 이름이나 위치가 조금 다를 수 있습니다. 못 찾겠으면 한컴 도움말에서 "누름틀"을 찾아 보세요.
- **누름틀 이름이 데이터의 키와 같아야 합니다.** 이름이 `성명`이면 데이터의 `성명` 값이, `applicant.name`이면 `applicant` 안의 `name` 값이 들어갑니다. 이름의 규칙은 `{{키}}`와 같습니다(글자·숫자·`_`·`-`, 점은 안쪽 항목). **이름에 공백·점·괄호가 잘못 들어 있어 이 꼴이 아닌 누름틀은 채우지 않고 그대로 두며**(건너뜀), 보고서에 "누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않았다"고 나옵니다. 화면의 대조표에도 "채우지 않음"으로 표시됩니다.
- 같은 이름의 누름틀이 문서에 여러 개 있으면 모두 같은 값으로 채웁니다.
- **여러 문단에 걸친 누름틀**(누름틀 안에서 Enter를 친 서식)은 한컴과 같은 방식으로 채웁니다: 첫 문단에 값이 들어가고, 그 사이에 있던 문단(표가 있으면 표도)은 지워지며, 끝 표식 뒤의 글은 첫 문단에 이어 붙습니다. 자리 목록에 "여러 문단에 걸쳐 있어 채우면 그 사이 문단이 합쳐짐"으로 미리 알리고, 결과의 "알림"에도 적습니다. 사이 문단이 지워지는 것이 싫으면 한컴에서 누름틀을 한 문단 안으로 다시 만드세요.
- 줄바꿈이 든 값으로 채운 결과 파일을 다시 서식으로 올려도 그 누름틀은 다시 채워집니다(옛 값이 통째로 바뀝니다).
- 여러 문단에 걸친 누름틀이라도 사이 문단에 구역 설정이 있거나 다른 누름틀과 엇갈려 있으면 채우지 않습니다. 자리 목록에 그 사유와 함께 "채울 수 없음"으로 미리 표시됩니다.
- 안에 그림·표가 들어 있거나, 표 칸 안에서 시작해 칸 밖에서 끝나거나, 끝 표식이 없는 누름틀은 값을 넣을 수 없어 그대로 두고 건너뜁니다. 1단계 자리 목록과 대조표에 "채울 수 없는 모양"으로 미리 표시되고, 보고서의 "건너뜀"에도 나옵니다.
- **메일 머지 필드**(한컴 메일 머지용 필드. 키가 들어 있음)는 누름틀처럼 채웁니다: 필드의 키를 데이터 키로 써서 표시 글을 값으로 바꾸고 필드는 그대로 둡니다. 키에 공백·괄호가 있으면 채우지 않고 알립니다. 메일 머지를 더 쓰지 않을 서식은 명령줄 `compile --merge-fields to-placeholder`(또는 `to-field`)로 `{{키}}`나 누름틀로 한 번에 바꿀 수 있습니다.
- 한컴의 다른 필드(책갈피, 날짜, 계산식, 키 없는 메일 머지 등)는 자리가 아니라서 건드리지 않고, 자리 목록에도 나오지 않습니다.
- 채울 수 있는 자리가 문서에 하나도 없거나, 가진 자리가 전부 건너뛰어지거나 "그대로 둠"이어서 **채운 자리가 하나도 없으면 그 건은 실패**입니다(원본과 같은 파일을 만들지 않습니다).

## 3. 데이터(JSON) 만들기

JSON은 데이터를 적는 약속된 글 형식입니다. 메모장 같은 편집기로 만들고 **UTF-8**로 저장하세요. 엑셀·CSV 파일은 올릴 수 없습니다.

**한 건**: 중괄호 하나. 문서의 `{{project.name}}`은 아래의 "알파 사업"으로 채워집니다.

```
{ "project": { "name": "알파 사업", "start": "2026-01-01" }, "manager": "홍길동" }
```

**여러 건**: 대괄호 안에 건마다 중괄호 하나. 건이 N개면 결과 파일도 N개입니다(한 번에 1000건까지).

```
[
  { "project": { "name": "알파 사업" }, "manager": "홍길동" },
  { "project": { "name": "베타 사업" }, "manager": "김철수" }
]
```

**묶음 형식**: `schema`를 적고 `data`에 위의 한 건 또는 여러 건을 넣습니다. `derived`는 `data`에 없는(또는 null인) 키를 보충하는 값이며 모든 건이 함께 씁니다.

```
{ "schema": "hwpx-studio/dataset@1", "data": [ { "manager": "홍길동" }, { "manager": "김철수" } ], "derived": { "회사": "예시 주식회사" } }
```

값으로 쓸 수 있는 것은 글자, 숫자, true/false입니다(숫자·true/false는 글자로 바뀌어 들어갑니다). 중괄호나 대괄호로 된 값(객체·배열)은 자리에 넣을 수 없습니다. 값이 `null`이거나 키가 없으면 "데이터에 없음"입니다. 여러 건의 데이터 항목 하나가 객체가 아니면 그 건만 실패합니다.

### 줄바꿈이 있는 값

JSON에서는 줄바꿈을 `\n`으로 적습니다. 예: `"주소": "서울시 가구\n나동 1번지"`. **줄바꿈이 든 값은 그대로 들어갑니다.** 값의 줄바꿈은 문서 안에서 같은 문단 안의 줄바꿈이 되고(문단이 나뉘지 않습니다), 탭(`\t`)은 탭이 됩니다. 윈도에서 만든 줄바꿈(`\r\n`)도 줄바꿈 하나로 들어갑니다. 대조표에는 "데이터 있음 — 값에 줄바꿈이 있음(그대로 들어감)", 결과의 "알림" 열에는 "값에 줄바꿈·탭이 있어 … 넣었습니다"라고 알려 주기만 하고, 오류나 건너뜀이 아닙니다.

글에 넣을 수 없는 제어 문자(보이지 않는 특수 문자)가 값에 있으면 그 건이 실패합니다. 다른 프로그램에서 복사한 글에 숨어 있는 경우가 있습니다. 대조표에는 "값에 넣을 수 없는 문자가 있음(U+0001 같은 코드)"으로 나옵니다.

## 4. 화면에서 하는 일

1. **문서 올리기.** .hwpx 파일을 고르면 문서에서 찾은 자리가 나옵니다: 누름틀 이름, `{{키}}`, 그리고 "후보 자리"(라벨 옆 빈 칸, `____`, `(   )`, `□` 같은 빈칸 표시). 후보 자리는 **알려 주기만 하고 채우지 않습니다.** 채우려면 한컴에서 `{{키}}`나 누름틀로 바꿔 주세요.
2. **데이터 올리기.** .json 파일을 고르면 "객체 하나/배열/묶음 형식"과 건수, 그리고 자리마다 데이터와 맞는지 보여 주는 표가 나옵니다.
   - **데이터 있음**: 채울 수 있습니다.
   - **데이터에 없음**: 데이터에 그 키가 없거나 값이 null입니다. 철자나 대소문자가 다르지 않은지 보세요.
   - **객체·배열이라 못 넣음**: 그 키의 값이 중괄호·대괄호로 되어 있습니다. 안쪽 항목(`키.이름`)을 쓰세요.
   - **데이터 있음 — 값에 줄바꿈·탭이 있음(그대로 들어감)**: 줄바꿈·탭이 든 값입니다. 문제가 아니라 알려 주는 것입니다.
   - **값에 넣을 수 없는 문자가 있음(U+0001 등)**: 글에 넣을 수 없는 제어 문자가 있어 그 건은 실패합니다. 3절을 보세요.
   - **이름이 데이터 키로 쓸 수 없는 꼴(공백·점 등)이라 채우지 않음**: 누름틀 이름을 고쳐야 합니다.
   - **채울 수 없어 채우지 않음**: 그 누름틀 안에 그림·표가 있거나, 표 칸 경계를 넘거나, 끝 표식이 없거나, 여러 문단에 걸쳤는데 사이 문단의 구역 설정·엇갈린 누름틀 때문에 합칠 수 없습니다(괄호 안에 사유). 한컴에서 한 문단 안의 글만 담는 누름틀로 다시 만듭니다.
   - **여러 문단에 걸쳐 있어 채우면 사이 문단이 합쳐짐**: 채울 수는 있지만 그 사이 문단이 지워집니다(2-2 참고).
   - **여러 문단에 걸쳐 있는데 채울 수 없음**: 사이 문단의 구역 설정이나 엇갈린 누름틀 때문입니다. 괄호 안의 사유를 보고 한컴에서 누름틀을 한 문단 안으로 다시 만듭니다.
   - 여러 건이면 "5건 중 2건"처럼 몇 건에서 그런지 함께 나옵니다. 아래 "데이터의 키 목록"에서 내 데이터에 어떤 키가 있는지 볼 수 있습니다.
3. **데이터에 없는 키는** 어떻게 할지 고릅니다.
   - **오류로 멈춤**(기본): 그 건은 만들지 않고 실패로 적습니다. 빠뜨린 값을 놓치지 않으려면 이 방식이 안전합니다.
   - **빈칸으로 채움**: 그 자리를 비웁니다.
   - **그대로 둠**: 그 자리의 글(`{{키}}` 또는 누름틀 안내문)을 그대로 남기고 나머지 자리만 채웁니다(남겨 둔 자리는 보고서에 따로 적히지 않습니다). 채울 자리가 하나도 없으면 그 건은 실패합니다.
4. **[생성]**을 누르면 건마다 결과가 나옵니다. 한 건이 실패해도 나머지는 만듭니다.
5. 건마다 **내려받기**를 누르면 그 파일을 받습니다. **미리보기**는 결과를 화면에서 읽기만 하게 보여 줍니다(고칠 수 없습니다). **폴더 열기**는 결과가 저장된 폴더를 탐색기로 엽니다.

채운 글이 문서에서 어떻게 보이는지는 한컴에서 직접 열어 확인해 주세요. 이상하게 보이면 어느 문서와 어느 데이터인지 알려 주세요.

## 5. 결과는 어디에 저장되나

- 만든 결과는 내려받기와 별도로 **작업 공간 폴더 안의 `out\날짜-시각\` 폴더**에도 저장됩니다. 예: `out\20261003-143005\`. 같은 시각에 두 번 만들면 `-2`가 붙습니다.
- 기본 작업 공간은 **내 사용자 폴더 안의 `HWPX Studio` 폴더**입니다. 다른 곳을 쓰려면 켤 때 `node apps/studio/server.ts --workspace 폴더이름`처럼 지정합니다.
- 파일 이름은 `원본이름-001.hwpx`, `원본이름-002.hwpx`처럼 건 번호(1부터)가 붙습니다. 한 건이어도 `-001`이 붙습니다. 이름에 쓸 수 없는 글자는 `_`로 바뀝니다. 실패한 건은 파일이 없습니다.
- 작업 공간에 처음 저장할 때 `workspace.json`이라는 작은 표지 파일을 만듭니다. **이미 다른 파일이 들어 있고 이 표지가 없는 폴더는 작업 공간으로 쓰지 않습니다**(아무것도 쓰지 않고 "저장하지 않았다"고 알립니다. 내려받기는 그대로 됩니다).
- **올린 원본 문서와 데이터는 디스크에 저장하지 않고**(프로그램이 켜져 있는 동안만 메모리에 있고, 끄면 사라집니다), 원본 파일도 고치지 않습니다. 저장되는 것은 만든 결과 파일뿐입니다.

## 6. 문제가 났을 때 보고서의 어느 줄을 볼까

생성 뒤의 결과 표에서 건마다 한 줄이 나옵니다.

- **결과**: 성공/실패.
- **채운 자리**: 그 건에서 값을 넣은 곳의 수입니다. 같은 키가 여러 곳이면 곳마다 셉니다.
- **건너뜀**: 채우지 않고 넘어간 자리와 이유입니다. 건너뛰어도 그 건은 성공일 수 있으니 꼭 읽어 보세요.
- **오류**: 실패한 이유입니다(붉은 글).
- **알림**: 실패도 건너뜀도 아닌 참고 사항입니다(예: 줄바꿈이 든 값을 넣었음).

건너뜀·알림 줄은 `[어느 자리] 쉬운 설명 코드` 모양이고, 오류 줄은 `쉬운 설명 코드`이며 어느 자리인지는 설명 안에 적힙니다. 코드(`DATA_MISSING` 같은 영문)는 사람에게 문의할 때 알려 주면 빨리 찾을 수 있습니다. 자주 만나는 줄:

| 줄에 나오는 말 | 하면 되는 일 |
| --- | --- |
| 데이터에 이 키의 값이 없습니다 | 데이터에 키를 더하거나, 철자를 맞추거나, 누락 정책을 바꿉니다 |
| 글자 모양이 중간에 바뀌어 있어 건너뛰었습니다 | 한컴에서 그 `{{키}}`를 지우고 같은 글자 모양으로 한 번에 다시 입력합니다 |
| 사이에 탭·줄바꿈·그림이 끼어 있어 건너뛰었습니다 | 한컴에서 `{{키}}`를 처음부터 끝까지 이어서 다시 입력합니다 |
| 값에 글에 넣을 수 없는 제어 문자가 들어 있습니다 | 데이터에서 그 값의 보이지 않는 문자를 지웁니다 |
| 객체나 배열이어서 자리에 넣을 수 없습니다 | 안쪽 항목의 키(`키.이름`)를 문서에 적습니다 |
| 이 누름틀은 안에 그림·표가 있거나, 표 칸 경계를 넘거나, 끝 표식이 없거나, 사이 문단에 구역 설정이 있거나, 다른 누름틀과 엇갈려 값을 넣을 수 없어 그대로 두었습니다 | 한컴에서 그 누름틀을 한 문단 안의 글만 담도록 다시 만듭니다 |
| 이 누름틀은 여러 문단에 걸쳐 있어서 첫 문단에 값을 넣고 그 사이 문단을 지웠습니다 | 알림입니다. 결과를 한컴에서 열어 사라진 문단이 없는지 확인합니다 |
| 누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 누름틀 이름을 글자·숫자·`_`·`-`(안쪽 항목은 점)로 고칩니다 |
| 메일 머지 필드의 키가 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않고 그대로 두었습니다 | 한컴에서 그 필드의 키를 고치거나, `compile --merge-fields`로 바꾼 뒤 `{{키}}`를 고칩니다 |
| 채운 자리가 하나도 없어 결과를 만들지 않았습니다 | 문서의 `{{키}}`·누름틀 이름과 데이터의 키가 맞는지 비교합니다. 누름틀 이름이 키와 같아야 합니다 |
| 이 파일은 .hwpx 문서가 아닙니다 / 옛 형식(.hwp)입니다 | 한컴에서 .hwpx로 다른 이름으로 저장해 다시 올립니다 |
| …새 오류가 생겨, 안전을 위해 결과를 만들지 않았습니다 | 프로그램이 안전 검사에서 멈춘 것입니다. 문서와 데이터를 알려 주세요 |

## 7. 지금의 한계

- **키에 공백·점이 들어 있으면 쓸 수 없습니다.** 엑셀 머리글처럼 "회사 이름", "금액(원)", "a.b"가 키인 데이터는 키 이름을 글자·숫자·`_`·`-`로 바꿔야 합니다(점은 안쪽 항목으로만 쓰입니다).
- **그림·도형 자리**: 그림 자체를 바꾸거나 그림·도형을 채우는 기능은 없습니다. 글상자·표·머리말·꼬리말·각주 안의 글은 채워집니다.
- **후보 자리**(빈칸 표시 등)는 알려 주기만 하고 채우지 않습니다.
- 여러 문단에 걸친 누름틀을 채우면 사이 문단이 지워집니다(한컴과 같은 동작). 지워지면 안 되는 내용이 사이에 있으면 누름틀을 한 문단 안으로 다시 만드세요.
- "그대로 둠"으로 남겨 둔 자리는 보고서에 따로 적히지 않습니다. 대조표의 "데이터에 없음"으로 어느 키가 없었는지 확인하세요.
- 값의 모양을 꾸미는 기능(금액에 쉼표, 날짜 형식)은 아직 없습니다. 데이터에 보이는 그대로 들어갑니다.
- 한 번에 1000건까지, 올리는 파일은 하나에 64MB까지입니다. 건이 많거나 문서가 크면 만드는 동안 화면이 잠시 멈춥니다.
- 만든 결과 파일에는 원본의 미리보기 글·그림과 작성자 정보가 그대로 남아 있을 수 있습니다. 밖으로 보내기 전에 한컴에서 확인하세요(정리 기능은 나중에 더합니다).
- 이 단계에서는 자리 연결을 화면에서 하지 않습니다. 문서 내용을 고치려면 한컴에서 고친 뒤 다시 올립니다.
