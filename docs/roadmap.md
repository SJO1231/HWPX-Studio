## 2차 — 화면과 추천

- rhwp 뷰어 통합: 렌더, 좌표↔앵커 변환. 시험 구현은 끝났다([뷰어 명세](viewer-spec.md)): 패치 없는 npm 배포본으로 클릭 위치를 엔진 주소로 옮긴다. 남은 것: 머리말·꼬리말·각주 안의 주소, 여러 문단에 걸친 선택, 묶음 개체 안 글, 글꼴 동봉.
- **사용자 결정(2026-10-03)**: 독립 설계자 권고대로 S1 앞에 **M1 빠른 생성**을 둔다(값의 줄바꿈, 여러 건 생성, 올리고 받는 한 쪽 화면, 사용자 안내). [스튜디오 명세](studio-spec.md) 4a절.
- 화면 조각의 순서와 범위는 [스튜디오 명세](studio-spec.md) 2절(S1 매핑 기본 → S2 원본 갱신과 자리 점검 → S3 조건 선택 → S4 데이터 묶음 → S5 추천 → S6 표 조정 → S7 조각 라이브러리 → S8 자동 초안 → S9 데스크톱 셸).
- **사용자 결정(2026-10-02)**: 편집창은 미루고, 검증된 뷰어 위에 매핑·조건 선택·표 조정 화면을 먼저 만든다(총괄의 권고를 사용자가 받아들임).
- 편집창이 붙기 전까지 문서 내용 수정은 한컴에서 하고 다시 불러온다. 이것은 **총괄의 임시 선택**이다(권고안에 딸려 있던 전제이며 사용자가 따로 정한 것이 아니다). 사용자의 원래 요구는 rhwp를 뷰어와 편집창으로 쓰는 것이므로 편집창은 미룬 것이지 뺀 것이 아니다.
- **사용자 결정(2026-10-02)**: 조건 분기 템플릿에 다음 둘을 넣는다. (1) 참조 번호 자동 재정렬: 조건으로 블록이 빠져도 본문의 "[붙임 2]" 같은 번호와 실제 순번이 맞게. (2) 상호 배타 규칙: 함께 참일 수 없는 조건을 선언하고 어기면 생성 전에 막는다. 조건 선택 조각(S3)에서 설계한다. 후보로만 남긴 것: 표준 문구와 최종 문구의 변경 대비표, 조건에 맞는 문서 여러 개의 묶음 생성.
- rhwp 편집창 통합(뒤로 미룸): rhwp 편집기 패키지는 그대로 쓰면 문서가 외부 호스팅으로 나가고 읽기 전용·문서 통째 교체 기능이 없어, 자체 빌드와 패치가 필요하다. 화면이 쓸 만해진 뒤 필요가 확인되면 붙인다. round-trip 게이트, 호스트 소유, 편집 결과 재파싱.
