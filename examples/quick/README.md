# 빠른 생성 예시 파일

빠른 생성 화면(또는 명령줄)을 바로 시험해 볼 수 있게 만든 예시입니다. 값은 전부 가짜입니다. 마음대로 고쳐서 시험해 보세요. 고치기 전에 복사해 두면 원래 모양으로 돌아오기 쉽습니다.

| 파일 | 무엇 |
| --- | --- |
| `template-fields.hwpx` | **누름틀**로 자리를 만든 서식. 누름틀 이름(= 데이터 키): `사업명`, `성명`, `소속`, `연락처`, `신청사유`, `신청일`. 표 안에 네 개, 본문에 두 개가 있습니다 |
| `template-braces.hwpx` | **`{{키}}`**로 자리를 적은 서식. 키: `사업명`, `성명`, `소속`, `연락처`, `신청사유`, `비고`, `신청일`. 표 안에 두 개, 본문에 다섯 개가 있습니다 |
| `data-single.json` | 한 건 데이터. 결과 파일 하나가 나옵니다 |
| `data-multi.json` | 세 건 데이터. 결과 파일 셋이 나옵니다. 둘째 건의 `신청사유`에 줄바꿈(`\n`)이, 셋째 건에 탭(`\t`)과 줄바꿈이 들어 있습니다 |
| `template-mailmerge.hwpx` | **메일머지**로 자리를 만든 합성 공고서 서식(한글 2024로 만듦). 메일머지 33곳(키 15개, 본문·표·머리말·꼬리말), 누름틀 4곳, 독립 `{{키}}` 8곳. 메일머지 4곳은 키에 공백·괄호가 있어 일부러 채우지 않는 자리입니다 |
| `data-mailmerge.json` | `template-mailmerge.hwpx`용 두 건 데이터. 둘째 건의 `사업명`에 줄바꿈, `장소`에 탭이 들어 있습니다 |
| `data-helper-export.json` | 같은 두 건을 **G2B Helper 내보내기**(`document-input.json`) 꼴로 싼 것. `format: "g2b-helper-document"`, `version: 1`, `source.tables`의 표 한 행이 한 건입니다 |
| `data-helper-request.json` | 같은 두 건을 **Helper 생성 요청** 꼴(`requestId`, `items[].fields`·`userValues`)로 싼 것. 항목마다 두 객체를 합쳐 한 건으로 봅니다 |
| `data-types.json` | 타입·라벨 연습용 두 건(작업창 표 보기, [사용 안내](../../docs/user-guide.md) 10절). 첫 건은 `template-braces.hwpx`를 채워 연습 문서를 만들 때(금액 `1,234,000원`, 날짜 `2026. 10. 7.`, 전화 `02-123-4567`), 둘째 건은 생성할 때 씁니다(금액 `2500000`, 날짜 `2026-11-02`, 전화 `031-987-6543`) |

두 서식은 같은 키를 쓰므로 어느 데이터와 짝지어도 됩니다. `비고`는 `{{키}}` 서식에만 자리가 있어서 누름틀 서식에서는 쓰이지 않습니다(문제 아님). 메일머지 서식은 `data-mailmerge.json`이나 두 Helper 예시와 짝지어 씁니다. 키 이름 규칙 밖 메일머지 4곳은 채우지 않고, 그 가운데 2곳(`{{참고 사항}}`, `{{계약 방법(수의)}}`)은 표시 글이 `{{…}}`라서 결과에 남습니다. 그래서 기본 설정(**해당 건을 실패로 처리**)에서는 두 건 모두 "실패 · 41곳 채움 · 남은 자리 2곳"이 정상이고, **원래 글 유지**로 바꾸면 "일부 채움 · 41곳 채움 · 4곳 건너뜀 · 남은 자리 2곳"으로 만들어집니다.

## 화면에서 시험하기

1. 저장소 폴더에서 터미널을 열고 아래를 입력합니다. 브라우저에서 `http://127.0.0.1:4318/quick`을 엽니다.

```
npm run start:lite
```

2. 왼쪽 **HWPX 문서 올리기**에서 `template-fields.hwpx` 또는 `template-braces.hwpx`를 고릅니다. **문서의 자리**에 찾은 자리(누름틀 이름, `{{키}}`)가 나옵니다.
3. 오른쪽 **JSON 데이터 올리기**에서 `data-single.json` 또는 `data-multi.json`을 고릅니다. **자리 · 데이터 대조표**에 자리마다 데이터와 맞는지 나옵니다.
4. **연결 확인 후 HWPX 생성**을 누르고 건마다 **내려받기**로 받습니다.
5. 받은 파일을 한컴에서 열어 값이 들어갔는지 봅니다.

### Helper JSON으로 시험하기

1. `/quick`에서 `template-mailmerge.hwpx`를 올립니다. 왼쪽 **문서의 자리**의 **규칙 밖 키**에 메일머지 3개 키(4곳)가 나옵니다.
2. `data-helper-export.json`을 올립니다. 데이터 칸에 "Helper JSON 2건(Helper 내보내기)", 대조표 위에 "Helper JSON 2건 · … · 규칙 밖 키 3개(채우지 않음)"가 나옵니다.
3. 그대로 생성하면 두 건 모두 실패하고, 오류 칸에 "남은 자리 2곳: {{참고 사항}} 1곳, {{계약 방법(수의)}} 1곳"이 나옵니다.
4. **값이 없을 때**를 **원래 글 유지**로 바꿔 다시 생성하면 두 건이 노란 "일부 채움 · … · 남은 자리 2곳"으로 만들어지고 알림 칸에 같은 키가 적힙니다.
5. `data-helper-request.json`으로 바꿔 올려도 결과는 같습니다. 이 파일의 한 항목에서 `userValues`의 `"담당자"`를 `"fields"` 쪽에도 넣으면 그 건만 "원천 값과 사용자 입력에 같은 이름이 있어" 실패합니다.

## 명령줄로 시험하기

한 건:

```
node apps/cli/src/main.ts fill examples/quick/template-fields.hwpx --data examples/quick/data-single.json -o result.hwpx
```

여러 건(`-o`는 **이미 있는 폴더**여야 합니다. 파일 이름은 `template-fields-001.hwpx`처럼 번호가 붙습니다):

```
node apps/cli/src/main.ts fill examples/quick/template-fields.hwpx --data examples/quick/data-multi.json --batch -o results
```

파일 이름을 데이터 값으로 짓고 싶으면 `--name "{{성명}}"`을 덧붙입니다(`홍길동.hwpx`, `김영희.hwpx`, …).

## 고쳐서 시험해 볼 거리

- **값 바꾸기**: 메모장 같은 편집기로 `.json`을 열어 값을 바꿉니다(UTF-8로 저장). 줄바꿈은 `\n`, 탭은 `\t`로 적습니다.
- **키 빼 보기**: `data-single.json`에서 `"연락처": ...` 줄을 지우면 대조표에 "데이터 없음 / null"이 나오고, 기본 설정(해당 건을 실패로 처리)에서는 그 건이 실패합니다. **값이 없을 때**를 "빈 글로 채우기"나 "원래 글 유지"로 바꿔 차이를 봅니다.
- **건 늘리기**: `data-multi.json`의 중괄호 덩어리를 복사해 네 번째 건을 만듭니다.
- **서식 고치기**: 한컴에서 서식을 열어 `{{키}}`를 더 적거나(같은 글자 모양으로 한 번에 입력), 누름틀을 더 넣고(이름 = 데이터 키) `.hwpx`로 저장합니다. 표 칸, 머리말·꼬리말 안에도 적어 볼 수 있습니다. 새로 적은 키는 데이터에도 더해야 합니다.
- **틀리게 해 보기**: `{{키}}`의 일부만 굵게 바꾸면 건너뜀 칸에 "글자 모양이 중간에 바뀌어 있어 건너뛰었습니다"가 나오고, 그 `{{키}}`가 결과에 남으므로 기본 설정에서는 그 건이 실패합니다(오류 칸 "남은 자리 1곳: …"). `{{키}}`에 공백·괄호를 넣어도(`{{신청 사유}}`) **규칙 밖 키**로 표시되고 결과에 남습니다. 누름틀 이름에 공백을 넣으면 "누름틀 이름이 데이터 키로 쓸 수 있는 꼴이 아니라 채우지 않았다"가 나옵니다.

자리 적는 규칙과 보고서 읽는 법은 [사용 안내](../../docs/user-guide.md)에 있습니다.

## 출처

두 서식은 한컴 오피스(한글 13)가 저장한 문서입니다. `python tools/com/make_examples.py`로 다시 만들 수 있습니다(한컴이 설치된 Windows). 저장할 때 들어가는 작성자 정보는 `synthetic`으로 바꿔 두었습니다.
